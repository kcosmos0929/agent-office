# 2단계 Codex 연결 — Task 0 확인 결과

- 날짜: 2026-10-24
- 환경: ChatGPT 데스크톱 앱 속 Codex(번들 codex-cli 0.162.0-alpha). 비교용으로 Homebrew CLI 0.142.0.
- 방법: 임시 탐침 훅(12개 사건)을 `~/.codex/hooks.json`에 넣었다. 사건 이름, 키 이름, 도구 이름, agent_id 유무만 기록했다(값은 기록 안 함). 확인 뒤 파일을 지웠다(원래 없던 파일).

## 판정: 계속 진행 (훅 방식 그대로)

| 확인 | 결과 |
|---|---|
| 사건이 오는가 | 옴. **새 훅은 신뢰해야 돈다**(신뢰 전엔 조용히 건너뜀). 신뢰 뒤엔 앱을 다시 켜지 않아도 바로 돈다. CLI는 `--dangerously-bypass-hook-trust`로 한 번 확인(6개 사건 정상). |
| 신뢰 위치 | 사용자 보고: 앱의 훅 화면에서 허용. 정확한 메뉴 경로는 확인 중. 신뢰 기록은 Codex가 `config.toml`에 직접 쓴다. 명령이 바뀌면 다시 신뢰해야 한다. |
| 타임아웃 | Codex는 **SessionEnd도 3초로 깎는다**(경고 "clamping SessionEnd hook timeout to 3s"). 설치 설정을 Interrupt·SessionEnd 3초로 고쳤다(b726b17). |
| 승인 | `PermissionRequest` 옴. 키: tool_name, tool_input(command, description), turn_id |
| 파일 수정 | 도구 이름 `apply_patch`, tool_input 키는 `command`(패치 원문) — 문서와 같음 |
| 도우미 | `SubagentStart`·`SubagentStop`에 agent_id·agent_type(`default`) 있음. 도우미 안의 도구 사건에도 agent_id 있음 — Claude와 같은 구조 |
| 도우미 도구 이름 | **문서와 다름**: 앱은 `collaborationspawn_agent`·`collaborationwait_agent`(묶음 이름이 앞에 붙음). 띄우기 입력 키는 task_name·fork_turns·message. 띄우기는 0.15초 만에 끝나고 실제 대기는 wait_agent 동안. 이름 끝부분으로 판정하고 wait_agent도 👥로, task_name을 이름표로 쓰게 고쳤다(1388715). |
| 중단 | `Interrupt` 옴(그 차례의 PostToolUse·Stop 없이). 서버는 Stop으로 바꿔 처리 — 계획대로 |
| SubagentStop 빈 출력 | Codex 로그 DB(`logs_2.sqlite`)에 훅 관련 경고 없음. 화면 경고는 사용자 확인 중 |
| 그 밖의 도구 이름 | `view_image`, `image_genimagegen`, `clockcurr_time`, `mcp__…` — 모두 ▶(실행)로 분류. 화면 이름이 조금 어색하지만 동작엔 문제없음 |

## 남은 것

- 신뢰 위치를 정확히 알면 `scripts/install.ts`의 `CODEX_TRUST_HINT` 문구를 고친다.
- 탐침 신뢰 기록은 `config.toml`에 남아 있다. Codex가 쓴 것이라 손대지 않는다(실행되는 것 없음).
- 첫 승인 확인(touch)은 오래된 대화에 걸려 있던 승인이 끝난 것으로 보여 앞쪽 사건이 없었다. 승인 사건 자체는 정리(rm) 때와 다른 대화에서 확인됐다.
