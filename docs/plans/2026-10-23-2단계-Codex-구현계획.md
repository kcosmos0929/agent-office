# 2단계 Codex 연결 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** ChatGPT 데스크톱 앱 안의 Codex가 일하는지·나를 기다리는지를 Claude처럼 목록형 상황판에 보인다.

**Architecture:**
- **훅**: 지금 훅 스크립트를 Codex에도 쓴다(인자 `codex` → `/api/codex/hook`). `apply_patch` 원문은 파일 이름으로 바꿔 보낸다.
- **수집기**: 새 수집기 `codexHook.ts`가 Claude 해석기를 '도구 방언(ToolDialect)'만 바꿔 재사용한다. 결과는 같은 상태 정리기에 `kind: 'codex'`로 넣는다.
- **설치**: `~/.codex/hooks.json`에 넣고 뺀다. Claude 설정과 같은 원문 비교 쓰기를 공용 함수로 뽑아 쓴다.

**Tech Stack:** Node 26(`.ts` 직접 실행) · TypeScript(검사만) · `ws` · `three` · Vite · `node:test`. 새 의존성은 없다.

**Spec:** `docs/specs/2026-10-23-2단계-Codex-연결-설계.md` (상태 규칙: `docs/specs/2026-10-23-A-정확도-설계.md`)

## Global Constraints

- **작업 폴더**
  - `~/developer/synthetic-office-accuracy`, 브랜치 `codex`(`main` c859a6e에서 분기)에서 일한다. 원래 폴더 `~/developer/synthetic-office`는 launchd가 돌리는 설치본이라 편집하지 않는다.
  - 디자인 세션이 `design` 브랜치에서 오피스 화면을 바꾸고 있다. 이번 계획에서 오피스 쪽은 `web/src/office/cast.ts` 한 줄(필터)만 건드린다.
- **코드 규칙**
  - TS는 지울 수 있는 문법만 쓰고, import에 `.ts`를 붙인다. 새 의존성은 없다.
  - 테스트는 `npm test`, 타입 검사는 `npm run typecheck`.
  - 커밋 끝에 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- **Codex 훅 명령(고정 — 신뢰가 해시에 묶임)**: `"<stableNodePath>" "<SO_HOME>/bin/claude-hook.mjs" codex`.
- **Codex 훅 사건 12개(이 순서)**: `SessionStart`, `SessionEnd`, `UserPromptSubmit`, `PreToolUse`, `PermissionRequest`, `PostToolUse`, `PreCompact`, `PostCompact`, `SubagentStart`, `SubagentStop`, `Stop`, `Interrupt`.
  - 타임아웃(초): 모두 5, `Interrupt`·`SessionEnd`만 3(Task 0 실측으로 SessionEnd 추가).
- **Codex 설정 파일**
  - 고치는 파일은 `~/.codex/hooks.json` 하나다. `~/.codex/config.toml`은 절대 고치지 않는다.
  - 고치기 전 백업은 `~/.claude/백업/codex-hooks-설치전-YYYY-MM-DD[-HHMMSS].json`(제거 땐 `제거전`).
- **개인정보**
  - `apply_patch`의 `tool_input.command`(패치 원문)는 보내지 않는다. `*** Add File: `·`*** Update File: `·`*** Delete File: ` 줄의 경로만 `tool_input.files`(최대 5개)로 보낸다.
  - `last_assistant_message`·`agent_transcript_path`·`model`은 보내지 않는다.
  - Codex 이벤트에는 `transcriptPath`·`title`을 싣지 않는다(게이지·제목 읽기 없음).
- **읽기 명령(📖)**: `cat` `rg` `grep` `ls` `sed` `head` `tail` `find` `wc`.
  - 맨 앞의 `bash -lc `·`bash -c `·`zsh -lc `·`zsh -c `·`sh -c `와 바깥 따옴표는 벗기고, 첫 단어(경로면 마지막 조각)로 판단한다.
- **이름**: `${KIND_LABEL[kind]} · 세션 ${hat + 1}` (`KIND_LABEL = { claude: 'Claude', codex: 'Codex' }`). 색은 `KIND_COLOR.codex` `#2F8F83`.
- **id**: `codex:<session_id>`. 상태 정리기의 세션 표는 지금처럼 `session_id`로 찾는다(Claude UUID와 Codex 세션 id는 형식이 달라 겹치지 않음).
- **오피스**: `kind === 'codex'`는 3단계 전까지 그리지 않는다. 목록형·알림음·배지는 Claude와 같게 동작한다.
- **설치·신뢰**: 다시 설치와 Codex 설정 변경은 사용자 허락 뒤에만 한다. 신뢰는 사용자가 Codex에서 한다.

**규칙**:
- `codexHookToEvents`
  - `Interrupt`면 `[{ ...base, type: 'stop' }]`, 그 밖은 `hookToEvents(payload, now, CODEX_TOOLS)`.

- `CODEX_TOOLS.classify`
  - `Bash` → `READ_COMMANDS.has(shellHead(command))`면 `reading`, 아니면 `running`
  - `apply_patch` → `editing`
  - `spawn_agent` → `delegating`
  - 그 밖은 `CLAUDE_TOOLS.classify`
- `CODEX_TOOLS.summarize`
  - `apply_patch` → `files`의 basename을 `, `로 이은 것(없으면 `'apply_patch'`)
  - `spawn_agent` → `description ?? agent_type ?? '도우미'`
  - 그 밖은 `CLAUDE_TOOLS.summarize`
  - 모두 `clip(…, 60)`
- `http.ts`: `POST /api/codex/hook`은 Bearer 토큰 필수(기존 규칙)이고 204를 돌려준다. 제목 가져오기·게이지 갱신은 하지 않는다.
