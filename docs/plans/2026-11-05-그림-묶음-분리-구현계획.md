# 그림 묶음 분리 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 공개 레포에는 코드와 처음부터 만든 대체 도트 사람만 남기고, 지금 캐릭터 그림은 비공개 `agent-office-art`로 옮겨 설치된 보드가 서버에서 갈아 끼워 쓰게 한다.

**Architecture:** 그림 폴더를 버전 없는 한 모양(`parts/…`, `seated/<모습>/…`, `pack.json`)으로 줄이고, 서버가 `/characters/` 요청을 설정 `charactersDir`의 유효한 묶음에서 보낸다(없거나 무효면 빌드된 대체 그림). 대체 그림은 제미나이로 글 설명만으로 만든 캐릭터를 도트로 옮겨 색을 바꾼다(설계서 5절, 2026-11-06 바뀜). 끝에 옛 커밋에서 그림 두 폴더를 거르고 최종 트리를 커밋 하나로 얹어 `agent-office`를 새로 만든다.

**Tech Stack:** TypeScript(Node 실행, `node --test`), Vite, three.js(손대지 않음), `node:zlib`(PNG), git filter-branch, gh.

**Spec:** `docs/specs/2026-11-05-그림-묶음-분리-설계.md`

## Global Constraints

- 새 npm 의존성 없음. PNG는 `node:zlib`로 쓰고 읽는다.
- **8번 작업 전에는 `agent-office`에 아무것도 올리지 않는다(push·PR 금지).** 커밋은 이 worktree의 로컬 `art-pack` 브랜치에만.
- 커밋 메일은 noreply(레포 로컬 설정 이미 있음). 커밋 끝에 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- `npm run install:office`·`uninstall:office`, 실제 `~/.synthetic-office/config.json` 수정, 레포 삭제는 **8번 작업에서 사용자 확인 뒤에만**. 시험 보드는 임시 `SO_HOME`.
- `~/.codex`·`~/.claude`는 건드리지 않는다.
- 그림 묶음 이름 값(그대로): hair `bun bob pony longbob` · face `neutral soft happy focused` · outfit `jp-classic jp-vest jp-suit kr-blazer kr-cardigan kr-shirt` · outfit layer `farArm farLeg nearLeg bottom torso nearArm accessory` · hair layer `hairBack head` · dir `SE SW NE NW` · lookId `JP01 JP02 JP03 KR01 KR02 KR03 EX1 EX2` · 앉은 dir `SE NW` · 앉은 part `body nearArm farArm`.
- 규격: 서기·걷기 시트 576×96(64×96 칸 × 9열: 0~7 걷기, 8 서기), 앉은 시트 512×960(8열 × 10행, 칸 0~71 일하기, 72~74 쉬기). 모두 RGBA 8비트(PNG color type 6). 묶음 = 312장 + `pack.json` `{"format": 1, "name": …}`.
- 화면·로그 문구는 한국어.

## Review Focus

1. **`charactersDir` 값 모양** — `~/…`, 끝 `/`, 상대 경로, 빈 문자열, 문자열 아닌 값: `~`는 홈으로 펴고, 상대·빈 값·비문자열은 무효(대체 그림 + 이유). → 3번 작업 테스트.
2. **경로 밖으로 나가는 요청** — `/characters/%2e%2e/%2e%2e/…`, `/characters/..%2f…`: 묶음 폴더 밖 파일을 절대 읽지 않고 404. → 3번 작업 테스트.
3. **묶음에 없는 파일** — 유효한 묶음에 없는 경로는 대체 그림으로 섞지 않고 404. → 3번 작업 테스트.
4. **zlib 판 차이** — Node가 바뀌면 같은 그림도 압축 바이트가 달라질 수 있다: `--check`는 바이트가 아니라 **픽셀**을 비교한다. → 4번 작업 테스트.
5. **대체 그림 정렬** — SW·NW가 SE·NE의 좌우 뒤집기이고, 서기 칸 가장 아래 불투명 줄이 88(발 기준점 y 88.5)이며 그 줄에 x 34(SE)가 들어간다. → 4번 작업 테스트 + 6번 화면 확인.
