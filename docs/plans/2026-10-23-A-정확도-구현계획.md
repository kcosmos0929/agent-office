# A 묶음(정확도) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 화면이 실제 상태와 어긋나는 장면을 없앤다. 대상은 승인 뒤에도 남는 ❗, 구분되지 않는 질문·한도·대화 정리, 보이지 않는 훅 없는 세션, 알 수 없는 훅 고장, 모르는 대화 찬 정도다.

**Architecture:**
- **신호 출처 두 가지를 더한다.**
  - Claude 앱의 세션 목록 파일 `~/.claude/sessions/*.json`을 2초마다 읽어 `OfficeState.applyRegistry`에 넣는다.
  - 새 훅 3개(PreCompact·PostCompact·StopFailure)는 기존 `hookToEvents`로 해석한다.
- **승인 순간**: 상태 정리기가 대기 종류(승인/질문)와 대기 시작 시각을 기억한다. 등록부가 그 뒤 `busy`로 바뀌면 승인한 것으로 본다.
- **대화 게이지**: 훅이 올 때 트랜스크립트 끝부분에서 숫자만 읽는다(세션당 5초 간격).
- **건강 정보**: 스냅샷에 `health`를 싣는다. 화면의 연결 띠와 `npm run doctor`가 함께 쓴다.

**Tech Stack:** Node 26(`.ts` 직접 실행) · TypeScript(검사만) · `ws` · `three` · Vite · `node:test`. 새 의존성은 없다.

**Spec:** `docs/specs/2026-10-23-A-정확도-설계.md` (바탕: `docs/specs/2026-10-22-synthetic-office-설계.md`)

## Global Constraints

- **작업 폴더**
  - 작업은 `~/developer/synthetic-office-accuracy`(브랜치 `accuracy`, `phase-1`에서 분기)에서 한다.
  - 원래 폴더 `~/developer/synthetic-office`에서는 편집하지 않는다. launchd가 그 폴더의 `src/server/main.ts`를 돌리기 때문이다.
  - 디자인 세션이 `~/developer/synthetic-office-design`(브랜치 `design`)에서 동시에 일한다. 겹치는 파일(`labels.ts`, `sort.ts`, `listBoard.ts`, `card.ts`, `bubbles.ts`, `pose.ts`, `style.css`)은 필요한 줄만 바꾼다.
- **코드 규칙**
  - TS는 지울 수 있는 문법만 쓰고, import에 `.ts` 확장자를 붙인다. 새 의존성은 없다.
  - 테스트는 `npm test`(직렬), 타입 검사는 `npm run typecheck`.
  - 화면 글자는 모두 `textContent`로 넣는다.
  - 커밋 메시지 끝에 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`를 붙인다.
- **새 상태 문구(정확히)**: question `❓️ 질문 대기` · compacting `🧹 대화 정리 중` · quota `⏳️ 토큰 기다림`
  - `️`는 그림 문자 고정용이다(픽셀 글꼴의 흑백 글리프 방지, 기존 ❗와 같은 이유).
- **묶음**: question `urgent` · compacting `working` · quota `rest`. 회보라 `QUOTA_COLOR = '#8E86A8'`.
- **정렬 순위**: permission 0 · question 0 · done 1 · (thinking·reading·editing·running·delegating·compacting) 2 · stalled 3 · quota 4 · idle 5 · gone 6. 같은 순위는 `since` 오래된 순.
- **등록부**
  - 읽는 필드는 `sessionId`, `pid`, `kind`, `cwd`, `name`, `status`, `statusUpdatedAt`뿐이다. 쓰기는 하지 않는다.
  - `kind === 'interactive'`만 쓴다. 2초마다 다시 읽고, 폴더 변화도 감시한다.
- **훅 스크립트**
  - 보내는 필드에 `trigger`, `error`만 더한다.
  - `compact_summary`, `custom_instructions`, `error_details`, `last_assistant_message`는 절대 보내지 않는다.
  - `HOOK_EVENTS`는 14개다.
- **게이지**
  - 끝 256KB만 읽고, 못 찾으면 1MB까지 늘린다.
  - 사용 토큰 = `input_tokens + cache_creation_input_tokens + cache_read_input_tokens + output_tokens`.
  - 하위 에이전트(`isSidechain`), `<synthetic>`, 0토큰 기록은 제외한다. 정리 경계 줄은 `"type":"system","subtype":"compact_boundary"`.
  - 세션당 5초 간격으로 읽는다. 비율은 내림 정수, 색은 <70 초록 · 70~89 호박 · ≥90 빨강.
- **'훅 없음' 판정**: 등록부 `busy`/`waiting`이 2분 넘게 이어졌고(서버 켜진 시각부터 잼), 서버가 켜진 뒤 그 세션의 훅이 0번일 때.
- **R2(연달아 대기)와 '늦은 알림 무시'**: 둘 다 `REGISTRY_WAIT_RULE`(Task 0 판정)이 참일 때만 켠다.
- **설치**: 다시 설치는 **사용자 허락 후, 원래 폴더에서만** 한다. 대화 내용은 저장하지도 보내지도 않는다.

## Review Focus

1. **서버를 막 다시 켰을 때 이미 열린 세션들**: 조용한(`idle`) 세션에 '훅 없음'이 붙거나 🟠 띠가 뜨면 안 된다. 일하던 세션도 서버가 켜진 지 2분이 지나기 전에는 안 된다. → Task 5 테스트.
2. **반쯤 쓴 등록부 파일, 폴더 일시 오류**:
   - 한 번 못 읽었다고 세션이 퇴근 처리되면 안 된다(두 번 연속일 때만 퇴근).
   - 읽기 실패(`error`/`missing`)일 때는 아무것도 바꾸지 않는다. → Task 4, Task 5 테스트.
3. **퇴근한 세션을 다시 열기(resume)**: 등록부에 다시 나타나면 되살아나야 한다. → Task 5 테스트.
4. **수백 MB짜리 트랜스크립트**: 끝 1MB까지만 읽고 그만둔다. 그보다 앞의 기록은 찾지 않는다(null). → Task 6 테스트.
5. **세션 도중 모델 변경**(예: Opus 5.5 → Haiku 4.5): 마지막 기록의 모델로 창 크기를 정한다(20만). → Task 6 테스트.

**`readContext`**:
- 크기 [256KB, 1MB] 순서로 파일 끝을 읽는다. 시작점이 0보다 크면 잘린 첫 줄을 버린다.
- 결과가 null이 아니거나 파일 전체를 읽었으면 그 결과를 돌려준다. 끝까지 못 찾으면 null.
- 파일이 없으면 null.

**refresher**:
- 세션별로 마지막 읽은 시각·대기 타이머·진행 중 여부를 기억한다.
- 경로가 없으면 아무것도 안 한다.
- `force`이거나 마지막 읽은 지 `minGapMs`(기본 5000) 지났으면 바로 읽는다.
- 아니면 남은 시간 뒤에 한 번 읽도록 예약한다(이미 예약돼 있으면 그대로).
- 진행 중이면 끝난 뒤 한 번 더 읽는다. 읽기가 실패해도 예외를 던지지 않는다.
- `setContext`가 true면 `onChange()`.
