# A 묶음(정확도) 진행기록

> 계획서 `2026-10-23-A-정확도-구현계획.md`를 실행하며 나온 실제 확인 결과·판정. 세부 결정(Ruling)은 PR #2 본문과 커밋에.

## Task 0 — 실제 확인 (2026-10-23)

감시 방법: 0.15초마다 `~/.claude/sessions/*.json`의 `status`·`statusUpdatedAt`과 오피스 스냅샷 상태 변화만 기록(설정 변경 없음, 대화 내용 없음). 시각은 UTC.

| 해 본 것 | 등록부 | 훅(오피스가 받은 것) | 판정 |
|---|---|---|---|
| 승인 (02:30:35) | `waiting`(35.52) → 승인 → `busy`(39.46) | PreToolUse(35.60) → PermissionRequest(35.74) → PostToolUse(40.37) | R1 맞음: busy가 대기 시작보다 뒤 → 바로 풀림 |
| **거절** (02:31:16) | `waiting`(16.62) → **`idle`(17.56)** | PermissionRequest(16.84) 뒤 **Stop 없음** — 다음 프롬프트(26.96)까지 ❗ | 설계 가정(거절도 busy) 틀림 → **R6 추가** |
| 질문 (02:31:30) | `waiting`(30.43) → 답 → `busy`(40.09) | PreToolUse AskUserQuestion(30.53) → PermissionRequest(30.65) → Notification permission_prompt(36.68) | PermissionRequest 옴 → 질문으로 분류, 6초 뒤 알림 무시 |
| `/compact` (02:31:58) | `busy` 17초 → `idle`(32:15.59) | (옛 설치엔 PreCompact 훅 없음) | 다시 설치 뒤 🧹 |

- 다른 세션(디자인 세션, 01:59·02:00)의 질문 두 번도 같은 순서(`waiting` → PermissionRequest +0.16초 → 알림 +6초 → 답하면 `busy`).
- `waiting`은 승인·질문 창이 떠 있을 때만 나타났다(세션 2개, 7번) → **`REGISTRY_WAIT_RULE = true`**.
- 상태값이 없는 등록부 파일이 몇 초 생겼다 사라짐(일회성 세션) → `statusUpdatedAt` 필수라 걸러짐.
- 3초 안 승인 뒤 늦은 알림·하위 에이전트 병렬 중 승인은 이번에 관찰 못 함 → 다시 설치 뒤 실제 확인 때.

## 실기록 재생

위 거절·질문 순서를 새 상태 정리기에 넣어 봄(2초 읽기 가정): 거절 뒤 ❗가 1초 안에 ✅ 내 차례로, 질문은 알림에도 ❓ 유지 → 답하면 💭.

## 전체 리뷰 (Fable)

Important 4개 수정(훅 없는 세션 깜빡임·남는 경보·퇴근 되살아남·늦은 승인 알림), Minor 8개 미룸(PR #2 본문). '응답 없음을 등록부 idle로 바로잡기'는 R6으로 해결.
