# Synthetic Office 설계서 (초안 — 검토 대기)

> **상태**: 브레인스토밍으로 정한 설계. 사용자 검토 전이라 workspace에 둔다. 승인되면 레포(`~/developer/synthetic-office/docs/`)로 옮기고 구현 계획을 세운다.
> 근거 세션: 2026-10-21~22 Claude Code 세션 (Pixel Agents 체험 → 대안 비교 → 직접 만들기로 결정)

## 1. 한 줄 요약

내 맥에서 도는 작은 서버가 **Claude · Codex · ARIA의 작업 신호**를 모아, 보조 모니터에는 **3D 블록 사무실**로, 맥 구석 작은 창과 폰·태블릿에는 **목록형 상황판**으로 실시간 보여준다. 이름은 디스코드 카테고리 'The Synthetic Office'에서 가져왔다.

## 2. 목적과 성공 기준

**가장 큰 목적 = 상황판** (사용자 선택). 곁눈질로 "누가 일하는 중이고, 누가 나를 기다리는지"를 바로 안다.

성공 기준:
1. Claude가 권한 승인을 기다리면 **2초 안에** 모든 화면에 주황 표시가 뜨고 알림음이 울린다.
2. 지금 하는 일(읽기·고치기·실행 등)과 **어느 프로젝트**인지가 이름표로 보인다.
3. 보조 모니터·맥 작은 창·폰·태블릿 모두 **주소 하나**로 본다.
4. 맥을 켜면 저절로 켜져 있고, 내가 신경 쓸 일이 없다.
5. 늘 켜두는 화면이라 **CPU를 거의 안 쓴다**(움직임 없을 땐 거의 그리지 않음).

### 사용자가 정한 것 / 내가 가정한 것

| 사용자가 정함 | 내가 기본값으로 둠 (바꿀 수 있음) |
|---|---|
| 목적 = 상황판 | 졸기 시작 30분, 퇴근 세션 목록 제거 10분 |
| 표시 정보 = 날 기다리는 중 · 지금 하는 일 · 어느 프로젝트 | '끝남·내 차례' 알림음 = 작게 한 번(끌 수 있음) |
| 사용량 = 사무실 안 작은 TV 전광판 | 회의실 = 하위 에이전트(도우미)가 일하는 곳 |
| 큰 화면 = 3D 블록 오피스, **전체 화면** | Claude 세션 구분 = 모자 색 |

| 순서 = Claude → Codex → ARIA | |
| 켜기 = 맥 켜면 자동 | |
| 안전 기본값(§8) 승인, 이름 = synthetic-office | |

## 3. 화면

### 3-1. 보조 모니터 — 3D 블록 오피스 (전체 화면)

- 비스듬히 내려다보는 고정 시점(아이소메트릭). 확대·축소만 된다.
- **방 4개**: Claude 작업실 · Codex 실험실 · ARIA 비서실 · 회의실.
- **벽에 TV 전광판**: 5시간 한도 %와 리셋까지 남은 시간(7일 한도는 작게).
- **캐릭터** = 블록 몸 + 블록 머리. 색은 Claude 주황(#D97757) · Codex 청록(#2F8F83) · ARIA 보라(#8B6CC9). Claude 세션이 여럿이면 **모자 색**으로 구분하고, 목록형에도 같은 색 표시를 넣는다.
- **자리**: Claude 작업실에 책상 4개, 세션이 더 많으면 줄을 늘린다(최대 8). 세션이 살아 있는 동안 같은 자리.
- **머리 위 말풍선**: 상태 + 프로젝트 이름(예: "✏️ 코드 수정 · 성수 LST").
- **캐릭터를 누르면 상세 카드**: 세션 제목, 상태와 경과 시간, 지금 하는 일(예: `Bash: python run_model.py`, 앞 60자까지), 프로젝트 이름, 폴더.
- **왼쪽 위 버튼**: ⧉ 작게 띄우기 · ☰ 목록 꺼내기 · 🔔 소리 켜기/끄기.

### 3-2. 작은 창 · 폰 · 태블릿 — 목록형 상황판

- 한 줄에 한 에이전트: 블록 얼굴 아이콘(모자 색) · 이름 · 상태 · 프로젝트 칩 · 세부 · 경과 시간.
- **정렬**: 승인 필요 → 끝남·내 차례 → 일하는 중 → 쉬는 중. 같은 묶음 안에서는 오래 기다린 순.
- 위쪽 띠에 "기다리는 중 N", 맨 아래에 사용량 전광판.

### 3-3. 화면 전환 규칙

- 창 폭 900px 이상이고 높이 600px 이상이면 오피스, 아니면 목록. ☰ 버튼으로 직접 바꿀 수 있다.
- **⧉ 작게 띄우기** = 크롬의 '항상 위에 뜨는 작은 창' 기능(Document Picture-in-Picture)으로 목록을 띄운다. 이 기능이 없는 브라우저면 작은 팝업 창으로 대신한다.
- 브라우저는 소리를 내려면 한 번 눌러줘야 하므로, 처음 열면 🔔 버튼이 "소리 켜기"로 깜빡인다.

## 4. 상태 모델

| 묶음 | 상태 | 언제 (신호) | 3D 오피스 | 목록 · 소리 |
|---|---|---|---|---|
| 🟠 급함 | ❗ 승인 필요 | 권한 요청 | 일어나 손 흔듦 + 바닥 주황 링 깜빡 | 맨 위 노란 띠 · **알림음** |
| 🟢 여유 | ✅ 끝남·내 차례 | 답을 마침 | 의자에 기대 대기, 초록 체크 | 다음 · 작은 알림음 한 번(끌 수 있음) |
| 🔵 일함 | 💭 생각 중 | 내 말을 받음 → 첫 도구 전 | 머리 위 점 세 개 | 행동 + 경과 시간 |
| | 📖 읽는 중 | Read · Grep · Glob · WebFetch · WebSearch | 모니터 보며 스크롤 | |
| | ✏️ 고치는 중 | Edit · Write · NotebookEdit | 빠르게 타이핑 | |
| | ▶ 실행 중 | Bash 등 실행 도구 | 모니터 진행 막대 (Codex는 서버랙 불빛) | |
| | 👥 도우미 투입 | 하위 에이전트 시작 | 같은 모자 색 작은 도우미가 회의실에서 일함 → 끝나면 퇴장 | |
| ⚪ 쉼 | 😴 쉬는 중 | '내 차례'로 30분 넘게 아무 일 없음 | 책상에 엎드려 졸기 | 아래쪽 흐리게 |
| | 👋 퇴근 | 세션 종료 | 문으로 걸어 나감 | 10분 뒤 목록에서 빠짐 |

- 그 밖의 도구(MCP 도구 등)는 '실행 중'으로 묶는다.
- Notification 훅의 '권한 요청' 알림도 '승인 필요'로 처리한다(PermissionRequest가 안 올 때의 대비).
- '생각 중'인데 15분 넘게 신호가 없으면 회색 "응답 없음"으로 바꾼다(앱이 강제 종료된 경우 대비). **도구 실행 중**(시작 신호만 오고 끝 신호가 아직 없는 상태)은 분석처럼 오래 걸릴 수 있으니 시간이 지나도 그대로 둔다.

## 5. 전체 구조

```
[신호]                        [내 맥 서버 :4310]                 [화면]
Claude 훅 ──────┐            ① 신호 모으기                    보조 모니터 → 3D 오피스
상태줄(사용량) ──┤  HTTP  →   ② 상태 정리(§4) + 프로젝트 이름표  → 맥 작은 창 → 목록형
Codex 기록 파일 ─┤  감시       ③ 화면에 실시간 전송(WebSocket)    폰·태블릿 → 목록형
ARIA 저장소 ────┘                     ↑
                         CnC 위키 프로젝트 허브(project_path)
```

### 5-1. 신호 수집기 (각각 독립된 부품)

| 수집기 | 방법 | 단계 | 확인 상태 |
|---|---|---|---|
| **Claude** | `~/.claude/settings.json`에 훅 스크립트 등록: SessionStart · UserPromptSubmit · PreToolUse · PostToolUse · PostToolUseFailure · PermissionRequest · Notification · Stop · SubagentStart · SubagentStop · SessionEnd. 스크립트는 받은 내용을 서버로 보내고(1초 제한) **항상 아무 출력 없이 성공으로 끝난다** | 1 | 2026-10-21 Pixel Agents 훅으로 데스크톱 앱 세션에서도 PreToolUse·PostToolUse가 오는 것을 확인 |
| **세션 제목** | 훅이 알려주는 대화 기록 파일에서 제목 줄(`custom-title`)만 읽는다. 대화 본문은 읽지 않는다 | 1 | 기록 파일에 제목 줄이 있는 것 확인 |
| **사용량** | 상태줄 명령을 등록해 `rate_limits.five_hour / seven_day`의 사용 %와 리셋 시각을 서버로 보낸다. 상태줄에는 짧은 한 줄(예: "5h 62% · 3:12")을 그대로 출력 | 1 | ⚠️ 문서상 Pro·Max 구독에서 제공. **데스크톱 앱 세션에서도 상태줄이 도는지 확인 필요**. 안 되면 대안을 따로 찾는다 |
| **Codex** | `~/.codex/sessions/YYYY/MM/DD/*.jsonl`을 감시. `task_started` → 일함, `custom_tool_call` → 실행 중, `task_complete` → 끝남 | 2 | 이벤트 종류 확인함. ⚠️ Codex의 '승인 대기' 이벤트 이름은 확인 필요 |
| **ARIA** | OpenClaw 저장소(`~/.openclaw/state/openclaw.sqlite`)를 **읽기 전용**으로 열거나 게이트웨이에서 상태를 받는다 | 3 | ⚠️ 6월 이후 기록이 파일이 아니라 DB로 옮겨짐. 2026-10-22 확인 시 게이트웨이가 꺼져 있었음. 구조 조사 필요 |

### 5-2. 프로젝트 이름표

- 서버가 켜질 때 `AI-Sessions/wiki/projects/*/00 * 허브.md`의 frontmatter에서 `project_path`와 프로젝트 이름을 읽어 "폴더 → 이름" 표를 만든다(현재 10개).
- 세션 폴더가 그 경로 안이면 그 이름, 아니면 폴더 이름을 쓴다. CnC Wiki 폴더는 "CnC Wiki".
- 허브 파일이 바뀌면 다시 읽는다. 위키는 **읽기만** 한다.

### 5-3. 서버 안의 부품

- **수집기들** (위 표): 각자 신호를 공통 형식의 '이벤트'로 바꾼다.
- **상태 정리기**: 이벤트를 받아 §4 규칙대로 에이전트별 상태를 갱신하고, 30분·10분·15분 타이머를 돌린다. 화면이나 수집기를 몰라도 되게 분리한다(테스트 쉽게).
- **전송기**: 상태가 바뀌면 연결된 모든 화면에 보낸다. 새로 연결된 화면엔 전체 상태를 한 번 보낸다.
- **화면 2종**: 3D 오피스와 목록형은 같은 상태 데이터를 받아 각자 그린다.

## 6. 만드는 순서

1. **1단계 — Claude**: 훅 + 세션 제목 + 사용량 + 프로젝트 이름표 + 목록형 + 3D 오피스 기본형(방 4개, 캐릭터, 말풍선, 상세 카드, TV) + 작게 띄우기 + 자동 켜기 + 폰 접속.
   - 맨 앞에서 '확인 필요' 두 가지(데스크톱 앱 상태줄, PermissionRequest가 데스크톱 앱에서 오는지)를 먼저 짧게 확인한다.
2. **2단계 — Codex 실험실**: 기록 파일 감시, 서버랙 연출.
3. **3단계 — ARIA 비서실**: OpenClaw 저장소 조사 → 읽기 방법 결정 → 연결.
4. 1단계가 안정되면 Pixel Agents 훅을 뺀다.

구현 계획은 **1단계만 먼저** 세운다. 2·3단계는 1단계가 끝난 뒤 각각 따로 계획한다.

## 7. 운영

- **자동 켜기**: 맥 로그인 시 launchd로 서버를 켠다. 죽으면 다시 켠다.
- **아이콘 앱 "Synthetic Office"**: 누르면 오피스 화면을 연다. 서버를 끄거나 다시 켜는 메뉴도 둔다. 현재 Pixel Agents 앱과 같은 방식.
- **설정 파일** `~/.synthetic-office/config.json`: 포트, 위키 경로, 30분·10분 같은 시간, 소리 켜기 여부.
- **기록**: `~/.synthetic-office/server.log`. 대화 내용은 남기지 않는다.

## 8. 안전 장치 (사용자 승인)

- **보기 전용**: 화면에서 승인·명령 기능 없음.
- **대화 내용 저장 안 함**: 지금 상태만 메모리에 둔다. 도구 이름, 파일 이름, 명령 앞부분만 다룬다.
- **접속 제한**: 기본은 이 맥에서만. 폰·태블릿은 집 와이파이에서 **비밀 토큰이 붙은 주소**로만. 토큰은 `~/.synthetic-office/token`(본인만 읽기). 설정 화면에서 폰용 QR 코드를 보여준다.
- **훅 안전**: 서버가 꺼져 있으면 바로 끝난다. 표준 출력에 아무것도 쓰지 않아 권한 결정에 끼어들지 않는다. 설치 전 `settings.json`을 `~/.claude/백업/`에 백업한다.
- 위키·OpenClaw 저장소는 읽기만.

## 9. 기술 선택 (제안 — 검토 때 바꿀 수 있음)

- 서버: Node.js(이 맥은 v26) + TypeScript. HTTP·WebSocket·파일 감시.
- 3D: three.js. 직교 카메라로 아이소메트릭 고정, 블록은 코드로 만든다(그림 파일 불필요). 글자(말풍선·카드)는 HTML로 겹쳐 그려 한글이 또렷하게.
- 화면 빌드: Vite.
- 테스트: Node 기본 테스트 도구.
- 레포: GitHub `synthetic-office` → `~/developer/synthetic-office/`.

## 10. 잘못됐을 때

| 상황 | 동작 |
|---|---|
| 서버 꺼짐 | 훅은 바로 끝남 · 화면은 "연결 끊김" 표시 후 자동 재연결 |
| '생각 중'으로 15분 넘게 신호 없음 | 회색 "응답 없음" (도구 실행 중은 제외) |
| 사용량 정보 없음 | 전광판에 "—" |
| 허브 파일 읽기 실패 | 폴더 이름으로 대신 |
| 포트 사용 중 | 기록 남기고 아이콘 앱에서 알림 |
| 브라우저가 작은 창 기능 미지원 | 팝업 창으로 대신 |

## 11. 확인 방법

- **자동 테스트**: 실제 신호에서 내용 부분을 지운 예시로 수집기·상태 정리기·이름표를 시험한다.
- **통합 확인**: 서버를 띄우고 예시 신호를 보내 화면 상태가 맞게 바뀌는지 본다.
- **화면 확인**: 브라우저로 직접 띄워 큰 화면·작은 창·폰 폭에서 캡처해 확인한다.
- **검토**: Claude가 구현하고 Codex가 코드를 검토한다(CnC 역할 분담).

## 12. 아직 확인할 것

1. 데스크톱 앱 세션에서 상태줄(사용량)이 도는가 → 1단계 맨 앞에서 확인.
2. 데스크톱 앱에서 PermissionRequest 훅이 오는가 → 1단계 맨 앞에서 확인.
3. Codex의 승인 대기 이벤트 이름 → 2단계.
4. ARIA 저장소 구조와 게이트웨이 상태 → 3단계.

## 13. 이번엔 안 하는 것

- 화면에서 승인하거나 명령 보내기
