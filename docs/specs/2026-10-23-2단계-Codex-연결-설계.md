# 2단계 Codex 연결 설계서 — 승인됨 (2026-10-23)

> **상태**: 2026-10-23 사용자와 정한 설계 1(신호와 상태)·설계 2(설치·확인·화면)를 글로 옮긴 것. 2026-10-23 사용자 승인 → 구현 계획 `docs/plans/2026-10-23-2단계-Codex-구현계획.md`.
> **바탕 문서**: `2026-10-22-synthetic-office-설계.md`(1단계, 5-1 'Codex 기록 파일 감시' 계획을 이 문서가 대체), `2026-10-23-A-정확도-설계.md`(상태 규칙).
> **근거**: Codex 공식 훅 문서 https://developers.openai.com/codex/hooks (2026-10-23 확인), 이 맥의 Codex 설치 관찰.

## 1. 한 줄 요약

**Codex도 Claude처럼 상황판에 보이게 한다.** Codex의 훅을 우리 서버로 보내 같은 상태 규칙으로 정리한다. 목록형에는 이번에, 오피스 개발실에는 디자인 병합 뒤에 보인다.

## 2. 확인된 사실 (2026-10-23)

| 확인한 것 | 결과 |
|---|---|
| Codex를 어디서 쓰나 | **ChatGPT 데스크톱 앱 안의 Codex**. ChatGPT.app 안에서 `codex app-server`로 돈다. 최근 세션 출처는 모두 'Codex Desktop'(엔진 0.162.0-alpha). 따로 깐 CLI는 0.142.0 |
| 훅 기능 | `codex features list`에서 `hooks` = stable·켜짐 |
| 훅 사건 | SessionStart · SessionEnd · UserPromptSubmit · PreToolUse · PermissionRequest · PostToolUse · PreCompact · PostCompact · SubagentStart · SubagentStop · Stop · **Interrupt** |
| 공통 입력 | stdin JSON: `session_id`, `transcript_path`, `cwd`, `hook_event_name`, `model`(+ `turn_id`, `permission_mode`) |
| 도구 이름 | 셸·`exec_command` → `Bash`, 파일 수정 → `apply_patch`(`tool_input.command`에 **패치 원문**), 도우미 → `spawn_agent`(앱은 `collaborationspawn_agent`·`collaborationwait_agent` — 2026-10-24 실측), MCP → `mcp__서버__도구`, 기타 함수 도구(`update_plan` 등)도 옴. 웹 검색 같은 호스팅 도구는 안 옴 |
| 도우미 | 하위 에이전트 훅은 **부모 `session_id`**. SubagentStart·Stop에 `agent_id`·`agent_type` |
| 훅 위치 | `~/.codex/hooks.json` 또는 `config.toml`의 `[hooks]`. 둘 다 읽음 |
| **신뢰** | 새 훅이나 바뀐 훅(내용 해시 기준)은 **사용자가 검토·신뢰해야** 실행된다. CLI에서는 `/hooks`에서 한다 |
| 기존 설정 | `config.toml`의 `notify`는 Computer Use 플러그인이 쓰는 중. 훅과는 별개라 건드리지 않음. 기존 `hooks.json` 없음 |
| Codex에 없는 것 | Notification(입력 기다림·승인 알림), StopFailure(한도), Claude 같은 세션 목록 파일 |

## 3. 범위

1. **신호**: 훅 스크립트를 Codex에도 쓰고, Codex 신호를 해석하는 수집기와 `codex` 종류 에이전트를 더한다.
2. **설치**: `~/.codex/hooks.json`에 우리 훅을 넣고 빼는 기능, 신뢰 안내, `npm run doctor` 두 줄.
3. **화면(이번)**: 목록형의 Codex 줄. 오피스에는 아직 그리지 않는다.
4. **화면(3단계, 디자인 병합 뒤)**: 개발실 캐릭터와 서버 랙 불빛. 범위와 순서만 정하고 구현 계획은 따로 세운다.

## 4. 신호와 상태 (설계 1)

### 4-1. 훅 스크립트

- 지금의 `claude-hook.mjs`를 그대로 쓰고, Codex용 명령에만 인자 `codex`를 붙인다. 인자가 있으면 `/api/codex/hook`으로 보낸다. 지금까지의 약속도 그대로다: 표준 출력에 아무것도 안 씀, 항상 exit 0, 2초 안에 끝.
- **보내는 필드**는 Claude와 같은 목록에서 고른다. Codex만의 처리는 셋이다.
  - `apply_patch`면 `tool_input.command`(패치 원문)를 **보내지 않는다.** 대신 `*** Add File:`·`*** Update File:`·`*** Delete File:` 줄에서 **파일 경로만** 뽑아 `tool_input.files`(최대 5개)로 보낸다.
  - `agent_id`는 지금 보내는 목록에 이미 있다. `model`은 쓸 곳이 없어 보내지 않는다(게이지 제외).
  - `last_assistant_message`·`agent_transcript_path`·프롬프트는 보내지 않는다.

### 4-2. 신호 해석 (새 수집기 `codexHook.ts`)

Claude 해석기(`claudeHook.ts`)의 공통 부분(요약·자르기·분류)을 재사용한다.

| Codex 신호 | 상태 |
|---|---|
| SessionStart | ✅ 끝남·내 차례 ('새 세션') |
| UserPromptSubmit | 💭 생각 중 |
| PreToolUse `Bash` | ▶ 실행 중. 단 명령 첫 단어가 읽기 명령(`cat`·`rg`·`grep`·`ls`·`sed`·`head`·`tail`·`find`·`wc`)이면 📖 읽는 중 |
| PreToolUse `apply_patch` | ✏️ 고치는 중. 상세는 파일 이름 |
| PreToolUse `…spawn_agent` · `…wait_agent` | 👥 도우미 투입 (이름표는 `task_name`) |
| PreToolUse MCP·기타 함수 도구 | ▶ 실행 중 (MCP는 `서버 · 도구`로 요약) |
| PostToolUse | 도구 끝 |
| PermissionRequest | 🛡️ 승인 확인 중 → **5초 넘게 안 풀리면** ❗ 승인 필요 (`agent_id`가 있으면 도우미의 대기). 2026-10-26 사용자 결정: Codex 앱 자동 승인(AutoReview)은 요청 신호를 먼저 보낸 뒤 AI가 허용해서, 바로 ❗면 아무도 안 기다리는데 ❗가 뜸. 자동 승인 여부는 신호·설정 파일로 알 수 없음 |
| SubagentStart · SubagentStop | 도우미 시작 · 끝 |
| PreCompact · PostCompact | 🧹 대화 정리 중 · 끝 (manual → ✅, auto → 💭) |
| Stop · Interrupt | ✅ 끝남·내 차례 |
| SessionEnd | 👋 퇴근 |
| 모든 신호, `transcript_path: null` (2026-10-27 추가) | **버림** — 기록 파일이 없는 일회용 세션(앱이 뒤에서 돌리는 '기억' 정리 등). 실측: `codex exec --ephemeral`은 시작·질문·끝·세션 종료 모두 null, 보통 세션은 파일 경로. 경로를 안 보내면(옛 버전) 그대로 해석 |

### 4-3. 상태 정리기

- 에이전트 종류(`AgentKind`)에 `codex`를 더하고, id는 `codex:<session_id>`로 한다.
- 상태 규칙은 Claude와 **같은 것**을 쓴다: 대기 종류, 도우미 대기 유지, 메인 차례가 끝나도 도우미가 일하면 👥, 15분 응답 없음, 30분 쉬는 중, 12시간 정리.
- **예외 — Codex 도우미는 그 차례에 묶는다**(2026-10-24 사용자 결정, 최종 리뷰 지적 ②~④): 중단(Interrupt)이면 도우미 표시·도우미 대기를 지우고 ✅, 새 질문이면 남은 도우미 표시를 지움, 차례가 끝난 뒤 도우미가 끝나면 💭가 아니라 ✅. **갱신(2026-10-26, 실측)**: Codex 도우미는 일이 끝나도 살아 있다가 다음 차례에 다시 쓰여서(followup_task·send_message, SubagentStop 없음) 차례 끝(Stop)은 도우미가 남아 있어도 **✅** — 살아 있는 도우미 수는 목록의 '도우미 N'으로만. 도우미를 기다리는 동안(wait_agent)은 👥. 이유: Codex엔 등록부·idle 알림처럼 틀린 👥·⚠를 바로잡는 장치가 없다. 대가: Codex 도우미가 정말 차례 뒤에도 일하면 👥가 안 보인다(메인 상태는 맞음).
- 세션 목록 파일 규칙(R1~R6)은 Claude 전용이다. Codex에는 그런 파일이 없다.
- 이름은 '`Codex · 세션 N`'이다. Codex 훅에는 세션 제목이 없고, 대화 내용에서 제목을 뽑지 않는다.
  - **갱신 (2026-10-26 사용자 결정)**: 이름 줄은 Claude·Codex 모두 '`플랫폼 · 제목`'(제목이 없으면 '`플랫폼 · 세션 N`'). Codex 제목은 Codex 앱 색인 `~/.codex/session_index.jsonl`의 id·제목만 읽는다(대화 기록·Codex 데이터베이스는 안 읽음, 못 읽으면 '세션 N'). 모델은 아는 때만 작은 표시(Codex = 모든 훅의 `model`, Claude = SessionStart의 `model` 또는 대화 게이지의 모델). 카드 머리줄은 '세션 N · 모델'.

### 4-4. Codex에서 빠지는 것

| 빠지는 것 | 이유 |
|---|---|
| ❓ 질문 대기 · ⏳ 토큰 기다림 | 해당 신호(Notification·StopFailure)가 없다 |
| 대화 게이지 | 사용자 결정. 공식 문서가 기록 파일 형식은 '안정적이지 않다'고 한다 |
| 승인 순간 잡기 | 세션 목록 파일이 없다. Codex는 승인한 도구가 **끝날 때** ❗가 풀린다(A 묶음 이전의 Claude와 같은 한계) |
| '훅 없음' 판정 | 세션 목록 파일이 없어 '훅 없이 일하는 세션'을 알 수 없다 |

## 5. 설치 · 신뢰 · 점검 (설계 2)

### 5-1. 설치 (`npm run install:office`)

- `~/.codex/`가 있으면 `~/.codex/hooks.json`에 우리 훅을 더한다. `config.toml`의 `[hooks]` 대신 JSON 파일을 쓰는 이유는 Claude 설정 병합 코드를 재사용할 수 있어서다.
  - 등록할 사건: SessionStart · SessionEnd · UserPromptSubmit · PreToolUse · PermissionRequest · PostToolUse · PreCompact · PostCompact · SubagentStart · SubagentStop · Stop · Interrupt (12개).
  - 명령: `"<node>" "~/.synthetic-office/bin/claude-hook.mjs" codex`. 타임아웃은 5초, Interrupt·SessionEnd만 3초(Codex 최대값 — 2026-10-24 실측: SessionEnd도 3초로 깎임).
- 보호 장치는 Claude 설정과 같다.
  - 남의 항목은 보존한다.
  - 쓰기 직전에 원문을 다시 비교하고, 바뀌었으면 다시 병합한다(3번 넘으면 중단).
  - 심볼릭 링크는 보존한다.
  - 쓰기 전에 `~/.claude/백업/codex-hooks-설치전-YYYY-MM-DD.json`으로 백업한다(파일이 있을 때).
- `~/.codex/config.toml`은 건드리지 않는다.
- `~/.codex/`가 없으면 이 단계를 건너뛰고 한 줄로 알린다.
- 제거(`uninstall:office`)는 우리 항목만 뺀다. **`hooks.json` 파일은 절대 지우지 않는다** — 남는 게 없으면 `{}`로 둔다(2026-10-26 사용자 결정, Codex 리뷰 P1: 바로가기의 원본·설치 전부터 있던 파일을 지울 수 있었음).

### 5-2. 신뢰 (사용자가 한 번)

- 설치가 끝나면 다음을 안내한다: "Codex에서 새 훅 12개를 검토·신뢰해 주세요(CLI는 `/hooks`)". 데스크톱 앱에서 어디서 하는지는 0단계에서 알아내 안내 문구에 넣는다.
- 신뢰는 훅 정의의 해시에 묶인다. 그래서 **명령 문자열을 고정**한다. 업데이트할 때는 `~/.synthetic-office/bin/claude-hook.mjs` 파일만 바꿔 다시 신뢰할 일이 없게 한다.

### 5-3. `npm run doctor`에 두 줄

| 이름 | 수준 |
|---|---|
| `Codex 훅 등록 (12개)` | ✓ / 빠진 사건이 있으면 ✗ / `~/.codex` 없으면 ⚠ "Codex 없음" |
| `마지막 Codex 훅` | ✓ "N분 전" / 아직 없으면 ⚠ "Codex에서 훅을 신뢰했는지 확인" |

`/api/health`에 `lastCodexHookAt`을 더한다. 기존 `lastHookAt`은 두 종류 모두의 마지막 신호다.

## 6. 화면

- **목록형 (이번)**: Codex 줄은 청록(`KIND_COLOR.codex` `#2F8F83`) 아바타, 이름 '`Codex · 세션 N`', 프로젝트 칩이다. 상태 문구·정렬·알림음·배지는 Claude와 같다. 연결 띠의 '신호 N초 전'에도 Codex 신호가 들어간다.
- **오피스 (이번)**: Codex 에이전트를 **그리지 않는다**(`kind === 'codex'` 제외). 지금 배치에는 Codex 자리가 없어 Claude 책상에 섞이기 때문이다. 알림음은 오피스 화면에서도 Codex 승인 대기에 울린다(스냅샷 기준이라 화면과 무관).
- **오피스 (3단계, 디자인 병합 뒤)**: 개발실 책상에 청록 캐릭터를 앉히고, 세션이 여럿이면 개발실 안에 자리를 더한다. ▶ 실행 중이면 서버 랙 불빛이 깜빡인다. 같은 오피스 코드를 건드리는 B 묶음과 함께 설계·구현한다.

## 7. 안전 · 개인정보

- 1단계 원칙을 지킨다: 보기 전용, 대화 내용 저장·전송 없음. 훅은 승인·차단 결정에 끼어들지 않는다(출력 없음).
- `apply_patch` 패치 원문, 프롬프트, 응답(`last_assistant_message`), 도구 결과는 보내지 않는다. 테스트로 확인한다.
- 새 주소는 `POST /api/codex/hook` 하나다. Bearer 토큰 필수로 기존 POST 규칙과 같다.
- 사용자 설정 파일(`~/.codex/hooks.json`)은 병합하기 전에 백업하고, 원문 비교 쓰기로 다룬다.

## 8. 만드는 순서

0. **확인 (사용자 도움 필요, 10분쯤)**
   - 신호 이름과 필드 **이름만** 적는(값은 적지 않는) 임시 훅을 `~/.codex/hooks.json`에 넣는다. 사용자 허락을 받고, 넣기 전에 백업한다.
   - 사용자가 Codex 데스크톱 앱에서 신뢰하고, 승인이 필요한 명령 1번·파일 수정 1번·도우미 1번을 시킨다.
   - 확인할 것: ① 데스크톱 앱에서 훅이 도는가 ② 신뢰는 어디서 하나 ③ 도우미 신호에 `agent_id`가 붙는가 ④ SubagentStop에 빈 출력을 내도 괜찮은가.
   - 끝나면 임시 훅을 지운다. 데스크톱 앱에서 훅이 안 돌면 멈추고 '기록 파일 감시'로 다시 설계한다.
1. 공통: `AgentKind` `codex`, 종류별 id·이름.
2. 훅 스크립트 `codex` 인자, `apply_patch` 파일명 추출.
3. 수집기 `codexHook.ts`와 `/api/codex/hook`.
4. 설치·제거(`hooks.json` 병합), doctor 두 줄, `/api/health`.
5. 목록형 Codex 줄, 오피스에서 Codex 제외.
6. PR → Codex 리뷰 → 병합 → 다시 설치(사용자 허락) → Codex에서 신뢰 → 실제 확인.
7. (3단계) 디자인 병합 뒤 개발실 캐릭터·랙 불빛 — 별도 계획.

## 9. 확인 방법

- **자동 테스트**
  - Codex 신호 예시(내용 뺀 것)로 4-2 표 전 줄을 확인한다.
  - `apply_patch` 원문이 안 나가고 파일 이름만 나가는지 본다.
  - 읽기 명령이면 📖, `spawn_agent`이면 👥인지 본다.
  - Interrupt가 ✅인지 본다.
  - `codex:` id와 이름을 확인한다.
  - `hooks.json` 병합: 남의 항목 보존, 중복 없음, 원문 비교 쓰기, 제거, `~/.codex` 없음.
  - doctor 두 줄을 확인한다.
  - 목록형 청록 줄과 오피스 제외를 확인한다.
- **실제 확인 (사용자와)**: 0단계, 다시 설치 뒤 승인·도우미·중단.

## 10. 아직 확인할 것

1. 데스크톱 앱에서 훅이 도는가, 신뢰는 어디서 하나 → 0단계.
2. 도우미 신호의 `agent_id`, SubagentStop 빈 출력 → 0단계.
3. Codex 엔진이 업데이트되면서 훅 신뢰가 다시 필요해지는 경우가 있는가 → 쓰면서 관찰.

## 11. 이번엔 안 하는 것

- 오피스 개발실 캐릭터·랙 불빛 → 3단계(디자인 병합 뒤, B 묶음과 함께).
- Codex 대화 게이지, 질문·한도 상태.
- 기록 파일 감시(0단계에서 훅이 안 될 때만 다시 검토).
- ChatGPT 일반 대화(훅 없음).

## 검토 때 봐 주세요 — 설계 1·2 뒤에 제가 정한 세부

1. **Bash 읽기 명령은 📖**: Codex는 파일을 셸 명령(`cat`·`rg`·`sed` 등)으로 읽는다. 첫 단어로 📖/▶를 가른다. 안 하면 Codex는 거의 항상 '▶ 실행 중'으로 보인다.
2. **훅 스크립트 하나로**: 새 스크립트를 만들지 않고 인자만 다르게 한다. 고칠 곳이 한 곳이다.
3. **오피스에서 당분간 안 그림**: 3단계 전까지는 목록형에서만 Codex가 보인다.
4. **SessionStart는 ✅ '새 세션'**: Claude와 같다.
