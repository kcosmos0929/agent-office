# B 묶음(생동감) + Codex 실험실 설계서 — 검토 대기 (2026-10-26)

> **상태**: 2026-10-26 사용자와 정한 설계 1~6부를 글로 옮긴 것. 사용자 검토 뒤 구현 계획 `docs/plans/2026-10-26-B-생동감-구현계획.md`을 세운다.
> **이어지는 순서**: A(정확도, 끝남) → 디자인(#9, 끝남) → **B(생동감) + Codex 실험실(이 문서)** → C(화면에서 승인·거절).
> **바탕 문서**: `2026-10-22-synthetic-office-설계.md`(1단계), `2026-10-23-A-정확도-설계.md`, `2026-10-23-2단계-Codex-연결-설계.md`(6장 "오피스(3단계)"), `2026-10-26-캐릭터-스프라이트-연결.md`.
> **이름 정리**: 이 문서의 'Codex 실험실'은 2단계 Codex 연결 설계서 6장의 "오피스(3단계, 디자인 병합 뒤)"다. 사무실 화면의 방 이름은 '개발실'. ARIA 비서실은 범위 밖이다.

## 1. 한 줄 요약

사무실이 **상태를 몸짓으로 보여 주고(손 흔들기·모니터·Zzz·점 세 개·반짝), 쉬는 사람은 휴게실로 가서 돌아다니고, 밤이 되면 어두워지게** 한다. 지금은 목록형에만 보이는 Codex 세션을 **개발실 책상**에 앉히고, 실행 중이면 짝지은 **서버 랙**이 깜빡이게 한다. 화면에 "누가 어디서 무엇을" 정하는 **연출 감독**(`director.ts`)을 새로 두어, 앞으로 움직임·그림을 계속 더하기 쉽게 만든다.

## 3. 범위

1. **서버**: 쉬기 10분·퇴근 2시간 규칙, Codex 💭 깜빡임, 새 버전이면 열린 화면 저절로 새로 고침.
2. **연출 감독**: 상태 → 자리·방향·자세·효과, 휴게실 쉬기와 자리 옮기기, "어디서든 → 어디로든" 걷는 길.
3. **몸짓·효과**: 손 흔들기(그림 칸 + 폴짝 대신), 모니터 움직임, Zzz, 점 세 개, 이벤트 반짝 두 가지.
4. **Codex 실험실**: 개발실 책상 3개, 청록 말풍선, 랙 불빛.
5. **낮밤 조명**.

이번에 안 하는 것은 14장.

## 4. 서버

### 4-1. 쉬기·퇴근 시간 규칙

```
✅ 끝남 ──(restMinutes 10분)──▶ 😴 쉬는 중(휴게실) ──(차례가 끝나고 leaveMinutes 120분)──▶ 👋 퇴근 ──(goneMinutes 10분)──▶ 숨김
   ▲                                   │                                               │
   └──────── 다시 말을 걸면(prompt·도구 시작 등 일하는 신호) ──────────────────────────────┘ → 출근해 자리로
```

- **2시간은 차례가 끝난 때(✅가 된 때)부터** 잰다. 쉬기 시작한 때부터가 아니다. 그래서 쉬기 10분 + 쉬는 중 110분이다.
- ⏳ 토큰 기다림은 이 규칙을 타지 않는다(한도가 풀리면 저절로 이어 감 — 자리에 남음). … 응답 없음도 그대로다.
- **자동 퇴근은 지우지 않고 숨긴다.** 창을 닫은 퇴근(SessionEnd)은 지금처럼 10분 뒤 지운다. 자동 퇴근은 세션이 아직 살아 있어서, 10분 뒤 `engaged = false`로 보드에서 숨긴다("열기만 한 세션"과 같은 방식). 숨기는 순간 모자·자리를 놓는다.
- **돌아옴**: 숨긴 세션에 일하는 신호가 오면 지금의 `engage()`가 비어 있는 모자·자리를 새로 주고 보드에 올린다. 화면에선 입구에서 걸어 들어온다. 12시간 신호가 없으면 지금처럼 정리한다(`forgetHours`).
- **등록부가 되살리지 않게**: 훅 없는 세션은 등록부 값을 그대로 비추는데(`mirror`), 등록부의 `idle`(→ ✅)이 😴·👋를 ✅로 되돌리면 안 된다. 등록부가 **자동 퇴근 뒤에 새로 바뀐** 값(`busy`·`waiting`, `statusUpdatedAt`이 퇴근 시각보다 뒤)일 때만 돌아온다. Claude(등록부 있음)·Codex(등록부 없음) 둘 다 테스트한다.
- **설정 이름은 새로**: `restMinutes`(기본 10), `leaveMinutes`(기본 120). 이 맥의 `~/.synthetic-office/config.json`엔 옛 기본값 `idleMinutes: 30`이 이미 적혀 있어서, 옛 이름을 쓰면 새 기본값이 안 먹는다. `idleMinutes`는 더 읽지 않고 파일에서 지우지도 않는다(`saveConfigPatch`는 남의 키를 보존).
- `goneMinutes`(10)는 그대로 쓴다.

### 4-2. 💭 깜빡임 (Codex만)

- **원인**: Codex가 도우미를 띄우는 도구(`spawn_agent`)가 끝나면 열린 도구가 0개라 `tool-end`가 💭 생각 중으로 바꾸고, 0.2~1초 뒤 기다리는 도구(`wait_agent`)가 시작되면 다시 👥가 된다.
- **고침**: Codex 메인의 **`spawn_agent`가 끝났을 때** 살아 있는 도우미가 있으면 💭 대신 **👥를 유지**한다. 다음 도구 시작·prompt·Stop이 평소대로 바꾼다.
- `wait_agent`가 끝난 뒤는 지금처럼 💭(메인이 결과를 받아 생각함). Claude는 바꾸지 않는다.

### 4-3. 새 버전이면 열린 화면이 저절로 새로 고침

- **빌드 지문**: 서버가 켜질 때 `dist/web/index.html`의 짧은 해시를 계산한다(이 파일은 내용 해시가 붙은 스크립트 이름을 담고 있어 빌드마다 바뀐다). 화면 빌드가 없으면 `null`.
- **전달**: `/api/client-config`의 `build`와 WebSocket 스냅샷 메시지의 `build`.
- **화면**: 처음 불러올 때 `client-config`의 `build`를 기억한다. 받은 스냅샷의 `build`가 `null`이 아니고 기억한 값과 다르면 **한 번만** 새로 고침한다. `sessionStorage`에 "이 지문으로 새로 고침함"을 적어 같은 지문으로는 다시 하지 않는다(무한 반복 방지). 기억한 값이 없으면(개발 서버 등) 새로 고침하지 않는다.
- **알려진 결과**: 크롬 '항상 위 작은 창'(PiP)은 새로 고침하면 닫힌다 — 다시 띄워야 한다(README·실행 명령어 문서에 한 줄).

## 5. 연출 감독 (`web/src/office/director.ts`, 새 파일)

### 5-1. 역할

- **입력**: 오피스에 그릴 에이전트들(스냅샷), 지금 시각(서버 시각 = 스냅샷 `now` + 받은 뒤 흐른 시간).
- **출력**: 세션(과 도우미)마다 **계획(Plan)** — `{ spot, facing, pose, pace, effects }`
  - `spot`: 머무를 바닥 점 / `facing`: 머무를 때 보는 화면 방향(SE·SW·NE·NW) / `pose`: 자세 이름(`pose.ts`) / `pace`: 거기로 갈 때 걸음(`work` 16장 · `free` 8장) / `effects`: 켤 효과 목록(`monitor`·`zzz`·`dots`·`wave`·`ring`)
- three.js·DOM을 모르는 **순수 함수**. 같은 입력이면 같은 출력이라 테스트하기 쉽고, 모니터·폰 등 **화면끼리 같은 장면**이 나온다(무작위 대신 세션 id 해시와 시각으로 정함).
- `cast.ts`는 계획을 **실행만** 한다: 계획의 `spot`이 지금 목적지와 다르면 길을 구해 걷고, 도착하면 `facing`·`pose`로 서고, `effects`를 켜고 끈다.
- 감독은 스냅샷이 올 때와 매 그리기마다 다시 계산한다(가벼움). 쉬는 화면은 1초에 한 번 그리므로 자리 옮기기 시각을 1초 안에 따라잡는다.

### 5-2. 상태 → 계획 표

| 상태 | spot | facing | pose | effects |
|---|---|---|---|---|
| 💭 생각 중 | 자기 책상 | 모니터 쪽 | think | monitor, dots |
| 📖 읽기 · ✏️ 고침 · ▶ 실행 · 🧹 정리 · 👥 도우미 | 자기 책상 | 모니터 쪽 | scroll / type-fast / think (지금 `pose.ts`) | monitor |
| 🛡️ 승인 확인 중(Codex) | 자기 책상 | 모니터 쪽 | think | monitor |
| ❗ 승인 · ❓ 질문 | 자기 책상 | **앞 방향**(NW→SW, NE→SE, SE·SW 그대로) | wave | wave, ring |
| ✅ 끝남 | 자기 책상 | 모니터 쪽 | lean-back | — |
| ⏳ 토큰 기다림 | 자기 책상 | 모니터 쪽 | sleep | zzz |
| … 응답 없음 | 자기 책상 | 모니터 쪽 | stand | — |
| 😴 쉬는 중 | **쉼 자리**(5-3) | 쉼 자리마다 정한 방향 | sleep | zzz (서 있을 때만) |
| 👋 퇴근 | 입구 | — | walk | — (도착하면 사라짐) |
| 도우미 | 회의실 의자(지금 `meetingSpot`) | 테이블 쪽 | type-fast | — |

- **자기 책상**: Claude 자리 0~7 = 사무실 책상(지금 `seatPosition`), Codex 자리 0~2 = 개발실 책상(7장). 그 밖(자리 없음·Codex 3번 이상) = 로비 대기 자리(지금 `waitingSpot`, 종류 구분 없이 차례로).
- **걸음**: 일을 받아 자리로 = `work`, 쉬러 가기·자리 옮기기·퇴근 = `free`(2026-10-26 디자인 세션과 정한 규칙).
- 표정은 지금 `faceFor`(상태별) 그대로다.

### 5-3. 쉼 자리와 자리 옮기기

- **쉼 자리**: 지금 `IDLE_SPOTS` 다섯 곳(자판기·소파·책장·커피머신·카페 테이블) + 넘칠 때 쓸 휴게실 안 서 있는 자리 3곳(좌표는 계획에서, 가구와 안 겹치게 화면으로 확인). 쉼 자리마다 보는 방향을 정한다(물건 쪽, 없으면 화면 쪽).
- **옮기는 때**: 세션마다 머무는 시간이 3~6분(세션 id 해시로 정함, 고정). 시간 칸 번호 = ⌊(서버 시각 + 세션별 어긋남) / 머무는 시간⌋.
- **고르는 법**: 바라는 자리 = (id 해시 + 칸 번호) mod 쉼 자리 수. 쉬는 세션을 id 순으로 줄 세워 차례로 자리를 받고, 이미 찬 자리면 다음 빈 자리로. 다 차면 넘침 자리, 그것도 다 차면 마지막 자리 옆(0.4칸)에 선다.
- **알려진 흔들림**: 누군가 새로 쉬기 시작하면 id 순서 때문에 다른 쉬는 사람의 자리가 바뀌어 걸어갈 수 있다. 상태가 없는 계산이라 화면끼리 같아지는 대가로 받아들인다.

### 5-4. 걷는 길 (`layout.ts`)

- **바닥 격자 방향만**(x만 또는 y만 바뀌는 구간) — 비스듬한 4방향 그림과 맞추는 규칙 그대로.
- **들어오는 길** `pathTo(dest)`(입구 → 목적지)에 새 목적지 세 종류를 더한다: 휴게실 쉼 자리(복도 → 휴게실 문 x=4.4), 탕비실 쉼 자리(휴게실을 지나 탕비실 문 x=11), 개발실 책상(가로 통로 → 유리벽 쪽 통로 → 개발실 문 y=3.3).
- **어디서든 → 어디로든** `routeBetween(from, to)`:
  - 모든 들어오는 길은 입구에서 가운데 입구 복도(x = 입구 x)를 따라 올라가다 한 점에서 갈라진다. 이 복도를 **등뼈**로 쓴다: `from`의 들어오는 길을 되짚어 등뼈로 나와 → 등뼈를 따라 → `to`의 들어오는 길로 들어간다. 입구 끝까지 내려갔다 오지 않는다.
  - **같은 방 안**(휴게실·탕비실끼리 포함)이면 등뼈로 나가지 않고 방 안 가로 길(계획에서 좌표)로 옮긴다.
- 지금 걷는 중에 목적지가 바뀌면, 지금 있는 점에서 새 길을 구한다(지금 `forwardFrom`·`backwardFrom`처럼 지금 구간에서 이어짐).

### 5-5. 화면을 막 열었을 때

- 지금처럼 처음 스냅샷은 걷지 않고 제자리에 바로 놓는다(쉬는 사람은 바로 쉼 자리에).

## 6. 몸짓·효과

### 6-1. 다섯 가지

| 효과 | 언제 | 어떻게 | 그리는 곳 |
|---|---|---|---|
| **손 흔들기** (`wave`) | ❗ · ❓ | 앞 방향으로 돌아서서 손 흔들기 그림 4장 반복(0.5초 한 바퀴). **그림이 없으면 폴짝**: 1초에 한 번, 0.25초 동안 2도트 위로(도트 단위로 딱 맞게) | 사람(기기 해상도) |
| **모니터 움직임** (`monitor`) | 일하는 중 | ▶ 실행 = 진행 막대가 2초에 걸쳐 차오르고 다시 / ✏️ 고침 = 글줄이 하나씩 늘어남 / 📖 읽기 = 줄이 위로 흐름 / 💭·👥·🧹·🛡️ = 커서 깜빡임. 그 밖의 상태는 지금 색(대기·끝남·꺼짐) 그대로 | 사무실(굵은 점) — 화면 판에 작은 캔버스 그림 |
| **Zzz** (`zzz`) | 😴 · ⏳ | 머리 위로 도트 글씨 Z 세 개가 차례로 떠오르며 흐려짐. 걷는 동안엔 안 보임 | HTML(CSS 움직임) |
| **점 세 개** (`dots`) | 💭 | 말풍선 💭 옆에 점이 하나·둘·셋 차례로 | HTML(CSS 움직임) |
| **이벤트 반짝** | 상태가 바뀌는 순간 | ① 일하던 세션이 ✅가 되면 머리 옆에 작은 ✅ 반짝 0.8초 ② ❗·❓가 일하는 중으로 풀리면 주황 링이 커지며 0.6초 만에 사라짐 | ①HTML ②사무실 바닥 링 |

- **CSS로 돌리는 것**(Zzz·점 세 개·✅ 반짝)은 사무실을 다시 그리지 않아도 움직인다 — 지금 `.bubble.urgent`의 깜빡임과 같은 방식.
- **이벤트는 실제로 바뀐 순간에만**: 화면을 열거나 서버에 **다시 연결한 뒤 첫 스냅샷은 기준으로만** 쓰고 이벤트를 만들지 않는다(끊긴 사이 바뀐 것까지 한꺼번에 터지지 않게). `main.ts`가 연결마다 첫 스냅샷임을 오피스에 알려 준다.
- **움직임 줄이기**: 기기 설정이 '동작 줄이기'(`prefers-reduced-motion`)면 CSS 움직임과 폴짝을 끄고 Z·점은 가만히 보인다.

### 6-2. 손 흔들기 그림 부탁 (Codex, 디자인 세션 경유)

- **자세**: 서서 한 손 흔들기, 4장 반복(0.5초 한 바퀴), 표정은 상태 표정(❗·❓ = 기본 `neutral`).
- **방향**: 앞 두 방향 SE·SW만(돌아서서 흔드니까). 칸 64×96, 앵커는 걷기·서기와 같음(SE [34, 88.5], SW [29, 88.5]).
- **부품 방식**: v15와 같이 머리·얼굴·옷 레이어 조합. 서기 그림에서 팔 레이어(`nearArm`·`farArm`)만 바꿔 되면 가장 좋고, 안 되면 필요한 레이어만 새로 — 가능 여부는 Codex 판단.
- **끼우는 곳**: 아틀라스에 열을 더하고 `pose`의 `wave` → 그 열. 그림이 없는 동안엔 서기 그림 + 폴짝(감독 표·효과는 바뀌지 않음).
- 부탁은 공유 노트로 디자인 세션에 넘기고, 디자인 세션이 지금처럼 Codex 그림 작업으로 묶는다. 이 설계는 그림 도착을 기다리지 않는다.

## 7. Codex 실험실

### 7-1. 자리

- `visible.ts`의 Codex 제외를 없앤다 — 오피스가 Codex도 그린다.
- 서버는 바꾸지 않는다: Codex 자리 번호는 지금도 Codex끼리 0~7로 매긴다. 화면에서 **0~2 = 개발실 책상**(`DEV_DESKS` 순서, x가 작은 쪽부터), **3 이상 = 로비 대기 자리**.
- **서 있는 자리**: 개발실 책상 앞 의자 쪽(+y). 큰 모니터를 보므로 **등이 보인다**(NE) — 사무실 바깥쪽(px) 자리와 같다. 앉기 그림이 오면 이 의자(`DEV_DESKS`의 의자)에 앉힌다(앉기 연결은 디자인 세션 몫).
- 길: 입구 → 가로 통로 → 유리벽 쪽 통로 → 개발실 문(벽 x=7.5, y=3.3) → 자기 책상(5-4).

### 7-2. 모습

- 머리·옷 조합은 Claude와 같은 모음에서 겹치지 않게(서버가 모자 번호를 종류 구분 없이 매김 — 지금 그대로).

## 8. 낮밤 조명 (`web/src/office/daylight.ts`, 새 파일)

- **해 시각**: 서울(위도 37.57°, 경도 126.98°, 한국 표준시)의 해 뜨는·지는 시각을 NOAA 근사식으로 계산한다(1~2분 오차, 인터넷 없음). 순수 함수.
- **밝기 단계** L(1 = 낮, 0 = 밤): 해 뜨기 30분 전 → 해 뜰 때 0 → 1, 해 질 때 → 30분 뒤 1 → 0. **6단계(0, 0.2 … 1)로 끊는다** — 도트 그림이라 계단식이 자연스럽고, 단계가 바뀔 때만 다시 그린다.
- **확인 주기**: 1분에 한 번 시각을 보고, 단계가 바뀌었으면 다시 그린다.
- **바뀌는 것**: ① 통창 밖 하늘·빌딩(낮 → 노을 → 밤: 남색 하늘·창문 불빛) ② 하늘 빛·해 빛 세기를 낮춤, 사무실 등(따뜻한 점 조명)은 그대로라 밤에 상대적으로 산다 ③ 모니터는 빛을 안 받는 재질이라 밤에 저절로 더 또렷하다. 그림자 방향은 움직이지 않는다.

- **미리 보기**: 주소에 `?clock=21:00`을 붙이면 그 시각(오늘 날짜)으로 그린다. 확인·캡처용.

- ARIA 비서실, 전용 작은 창 앱, CI, 데스크톱 앱 사용량 출처(허브 후속 과제 그대로).
- 일하는 중 돌아다니기(기각), 움직이는 그림자, 펫·꾸미기.
- 4번째 이상 Codex용 개발실 자리 추가(로비 대기로 처리).

## 검토 때 봐 주세요 — 설계 1~6부 뒤에 제가 정한 세부

결정에 가까운 것들이라 따로 모았다. 바꾸고 싶은 게 있으면 말해 주세요.

1. **2시간은 차례가 끝난 때부터**(쉬기 시작부터가 아님).
2. **자동 퇴근은 숨김, 창 닫은 퇴근은 지움**. 돌아오면 모자·자리를 새로 받는다(지금의 '다시 열기' 규칙과 같음) — 전과 다른 모습·자리일 수 있다.
3. **⏳ 토큰 기다림은 자리에서 Zzz**(휴게실로 안 감).
4. **💭 고침은 `spawn_agent`가 끝날 때만**(`wait_agent` 뒤는 💭 유지).
5. **쉼 자리 3~6분, 서버 시각 기준**.
6. **이벤트는 두 가지만**(✅ 반짝, 링 퍼짐) — 더 원하면 B-2로.
7. **'동작 줄이기' 기기 설정이면 움직임 끔**.
8. **4번째 Codex부터 로비 대기**.
9. **낮밤 6단계, 1분마다 확인**, 그림자 방향 고정.
10. **승인 대기 그리기 속도 16 → 8**.
