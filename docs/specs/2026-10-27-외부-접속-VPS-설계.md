# 외부 접속(VPS) 설계서 — 승인됨 (2026-10-27)

> **상태**: 2026-10-26~27 사용자와 토의해 정한 것을 글로 옮김. 사용자 승인("이 설계대로 설계서 쓰고 진행해 줘", 2026-10-27).
> **바탕**: VPS·터널 구성은 CnC Wiki `library/global/ai-it/원격-SSH-접속-구성` 「Synthetic Office 외부 접속」(시험 입구까지 해 둠).

## 1. 한 줄 요약

같은 Wi-Fi가 아니어도 **나만** 폰으로 보드를 본다. 맥이 VPS로 리버스 터널을 열고, VPS의 Caddy가 `https://1-2-3-4.sslip.io:8443`으로 받아 터널로 넘긴다. 보드 서버에는 **터널 전용 문**을 따로 열어, 그 문으로 온 접속은 언제나 바깥 접속으로 다룬다(보기만).

## 2. 사용자와 정한 것

| 정한 것 | 내용 |
|---|---|
| 길 | Tailscale(학교망 차단) 대신 **기존 Oracle VPS**(연구실·집 터널과 같은 VPS) |
| 포트 | 443은 sshd(22 막는 망 폴백) → HTTPS는 **8443**, 80은 인증서 확인·8443으로 넘기기만 |
| 주소 | 가입 없는 **sslip.io**, Let's Encrypt 인증서(Caddy 자동 갱신) |
| 보안 | HTTPS + 토큰 + 터널 전용 문 + 제한 키 + 토큰 새로 받기. 아이디·비밀번호 추가 잠금은 안 함 |
| 기본값 | 외부 접속은 **설정해야만 켜짐**(기본 꺼짐) |

## 3. 왜 전용 문이 필요한가

맥의 ssh가 터널 끝을 맥 안 주소(127.0.0.1)로 이어 주므로, 지금 서버는 터널로 온 요청을 **맥 안(루프백)** 으로 본다. 그러면 토큰 없이 열리고, 설정 바꾸기·토큰 보여 주기(`/api/lan-info`)까지 밖에서 된다. → 터널은 지금 문(4310)이 아니라 **새 문(4311)** 에만 잇고, 그 문은 보낸 주소와 상관없이 늘 바깥으로 다룬다.

## 4. 보드 서버 (PR 1)

### 4-1. 설정 (`config.ts`)
- `remotePublicHost: string | null` — 기본 `null`(꺼짐). 예: `"1-2-3-4.sslip.io:8443"`. 폰 주소창에 보이는 그대로(포트 포함).
- `remotePort: number` — 기본 `4311`. 터널이 잇는 맥 안 포트.
- 바꾸면 서버를 다시 켜야 반영(설정 창 '다시 켜기').

### 4-2. 보기 토큰 (`token.ts`)
- 훅·관리용 토큰(`token`)과 **따로** `viewer-token` 파일(32바이트 hex, 0600). 새면 보기만 되고, 훅·관리엔 못 쓴다.
- `rotateViewerToken(home)` — 새로 만들어 파일에 쓰고 돌려준다.

### 4-3. 터널 전용 문 (`http.ts`)
`remotePublicHost`가 있을 때만 `127.0.0.1:remotePort`에 두 번째 HTTP 서버를 연다(0.0.0.0 아님). 이 문의 규칙:
- **Host**: `remotePublicHost`와 정확히 같아야(대소문자 무시) — 아니면 403. IP·localhost도 403.
- **메서드**: GET·HEAD와 WebSocket(`/ws`)만. POST 등은 405 → 훅·사용량·관리 명령은 이 문으로 못 들어온다.
- **토큰**: `?token=<보기 토큰>`이면 쿠키 `so_view`(HttpOnly·**Secure**·SameSite=Strict·1년)를 주고 토큰 없는 주소로 302. 그 밖엔 `so_view` 쿠키가 보기 토큰과 맞아야(아니면 401). 훅 토큰·`so_token` 쿠키는 이 문에서 통하지 않는다.
- **막는 길**: `/healthz`·`/api/lan-info`·`/api/remote-info` → 404. `/api/client-config`는 `loopback: false`(설정 창 안 뜸).
- **WebSocket**: Origin이 `https://<remotePublicHost>`(또는 없음)이고 `so_view`가 맞아야.
- `X-Forwarded-For` 등 머리말은 믿지 않는다.

### 4-4. 지금 문(4310)에 더하는 것 (맥 안에서만)
- `GET /api/remote-info`(루프백만): `{ url: "https://<host>/?token=<보기 토큰>", qrSvg }`, 꺼져 있으면 `{ url: null, qrSvg: null }`.
- `POST /api/admin/remote-token`(루프백 + `x-so-admin` + 같은 출처): 보기 토큰을 새로 받고, **열려 있는 바깥 WebSocket을 모두 끊는다**(옛 토큰으로 보던 화면은 바로 끊김). 204.

### 4-5. 설정 화면 (`web/src/settings.ts`)
- 새 칸 **'밖에서 보기'**: QR + 주소(토큰은 `…`로 가림) + **'토큰 새로 받기'** 버튼(확인 창 → 새로 받은 뒤 QR 다시 그림).
- 꺼져 있으면 "꺼져 있어요 — config.json의 remotePublicHost" 한 줄.

## 5. 터널·VPS (PR 1 뒤, 단계마다 사용자에게 먼저 여쭘)

1. **열쇠**: 맥에 터널 전용 키 `~/.synthetic-office/tunnel_ed25519`(암호 없음, 0600). VPS `~ubuntu/.ssh/authorized_keys`에 `restrict,port-forwarding,permitlisten="localhost:24310" ssh-ed25519 … synthetic-office-tunnel` — 이 키로는 24310 하나 여는 것 말고 아무것도 못 한다.
2. **터널 유지**: launchd `com.synthetic-office.tunnel`(KeepAlive): `ssh -N -T -i <키> -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -o ServerAliveCountMax=3 -o StrictHostKeyChecking=yes -R localhost:24310:127.0.0.1:4311 ubuntu@<VPS>`. VPS 쪽 24310은 VPS 안에서만 열린다(iptables도 막음).
3. **Caddy**: 시험 `respond` 자리를 `reverse_proxy localhost:24310`으로(WebSocket 포함, Host 그대로 넘김).
4. **설정**: `config.json`에 `remotePublicHost` 넣고 서버 다시 켜기 → 설정 창 QR을 폰으로 한 번 찍기.
5. 터널 키·plist 만들기는 `npm run remote:tunnel`(설치/제거) 같은 작은 스크립트로 — 세부는 PR 2에서.

## 6. 확인 방법

- **PR 1 테스트**(node:test, `startServer` 두 문):
  - 전용 문: 쿠키 없음 401 · 훅 토큰 쿠키(`so_token`) 401 · `?token=보기` → 302 + `Secure` 쿠키 · 그 쿠키로 200 · POST 훅(Bearer 맞아도) 405 · admin 405 · `/api/lan-info`·`/api/remote-info`·`/healthz` 404 · Host가 다르거나 IP면 403 · WebSocket 쿠키 없음 401, 맞으면 스냅샷 · 다른 Origin 403.
  - 지금 문: 루프백 `remote-info`(꺼짐 null / 켜짐 주소에 보기 토큰) · 바깥은 404 · `remote-token` 새로 받기 → 옛 쿠키 401·바깥 WebSocket 끊김 · 기존 테스트 그대로 통과.
  - 설정 기본값(`remotePublicHost: null`, `remotePort: 4311`) · `viewer-token` 0600·다시 읽으면 같음·새로 받으면 다름.
- **격리 서버**: 두 문을 띄워 `curl -H 'Host: …'`로 위 규칙 확인.
- **실제**(5장 뒤): 폰 LTE·학교 Wi-Fi에서 QR → 목록형·사무실, 토큰 새로 받기 → 옛 폰 끊김.
- 리뷰: `codex exec`(gpt-6.1-sol·high, 임시 사본·인터넷 없음) — 작은 PR 리뷰 방식(사용자 결정).

## 7. 잘못됐을 때

- `remotePublicHost`가 없거나 4311을 못 열면: 전용 문 없이 지금처럼 동작(경고 한 줄). 4310은 영향 없음.
- 터널이 끊기면 VPS에서 502 — 맥의 보드는 그대로. launchd가 다시 잇는다.
- 보기 토큰이 새면: 설정 창 '토큰 새로 받기'.

## 8. 이번엔 안 하는 것

- 아이디·비밀번호 추가 잠금(필요해지면 Caddy `basic_auth`).
- 밖에서 설정 바꾸기·승인(C 묶음과 함께 따로 설계).
- 443을 sshd와 나눠 쓰기(학교 Wi-Fi가 8443을 막을 때만).
