# 그림 묶음 분리 — 코드만 공개하기 설계

- 날짜: 2026-11-05
- 상태: 사용자 승인(설계 1·2·3, 대화) → 이 문서 검토 대기
- 브랜치: `art-pack` (worktree `~/Developer/synthetic-office-artpack`) — **이력 정리가 끝날 때까지 GitHub에 올리지 않는다**

## 1. 목표

- 공개 레포 `agent-office`에는 **코드와 처음부터 만든 대체 도트 사람**만 둔다. 지금 캐릭터 그림과 그 그림이 찍힌 화면 캡처는 **파일과 이력 모두에서** 뺀다.
- 사용자 맥에 설치된 보드는 지금 그림을 그대로 보여 준다. 지금 그림은 새 비공개 레포 `agent-office-art`에 둔다.
- 남이 레포를 받아 설치하면 대체 도트 사람으로 모든 기능(걷기·서기·앉기·쉬기)이 돈다.

하지 않는 것: 공개 전환, 저작권자 이름 확정(`LICENSE`의 이름 자리는 비워 두고 공개 전에 채운다), 앱 동작 변경.

## 3. 그림 묶음(art pack) 모양

버전 폴더(`v15`·`v18`·`v19`·`seated-v29`)와 그 사이 물러서기를 없애고 한 모양으로 줄인다.

```
characters/
  pack.json                                     {"format": 1, "name": "<묶음 이름>"}
  parts/hair/<hair>/{hairBack,head}/<DIR>.png   576×96  (hair 4 × 2 × 4방향 = 32)
  parts/face/<hair>/<face>/<DIR>.png            576×96  (4 × 4 × 4 = 64)
  parts/outfit/<outfit>/<layer>/<DIR>.png       576×96  (6 × 7 × 4 = 168, layer = farArm farLeg nearLeg bottom torso nearArm accessory)
  seated/<lookId>/{SE,NW}/{body,nearArm,farArm}.png   512×960 (8 × 2 × 3 = 48)
```

- `<DIR>` = SE·SW·NE·NW, `<hair>` = bun·bob·pony·longbob, `<face>` = neutral·soft·happy·focused, `<outfit>` = jp-classic·jp-vest·jp-suit·kr-blazer·kr-cardigan·kr-shirt, `<lookId>` = JP01·JP02·JP03·KR01·KR02·KR03·EX1·EX2. 이름은 지금 코드(`look.ts`·`seated.ts`)의 값을 그대로 쓴다.
- 칸 규격·기준점·칸 번호 규칙은 지금과 같다(서기·걷기 64×96 칸 9열, 앉기 8열 × 10행 = 일하는 칸 0~71 + 쉬기 72~74). 규격은 코드 상수가 정본이고, `layout.json`·`catalog.json`은 묶음에 넣지 않는다(실행 중엔 쓰지 않음).
- 지금 그림 묶음 = `v19/parts` + `seated-v29`를 이 모양으로 복사(지금 앱이 실제로 읽는 파일과 바이트 단위로 같아야 한다 — 312장).

## 4. 코드

- `look.ts`: `partFiles`가 경로 하나 `parts/...`만 돌려준다. `PART_BASE`·`OUTFIT_VERSION`·`HAIR_VERSION` 삭제.
- `seated.ts`: `SEATED_BASE = 'seated'`.
- `compose.ts`·`atlas.ts`: 손대지 않는다(후보 목록을 받는 구조라 후보가 하나여도 그대로 동작).
- **서버(`http.ts` `serveStatic`)**: 요청 경로가 `/characters/`로 시작하고 유효한 `charactersDir`가 있으면 그 폴더에서 보낸다. 그 폴더에 없는 파일은 404(대체 그림으로 섞지 않음). `charactersDir` 밖으로 나가는 경로는 404(지금 화면 폴더와 같은 막기).
  - 유효 = 설정값이 있고(`~`는 홈으로), 폴더가 있고, `pack.json`이 있고 `format`이 1. 아니면 대체 그림(`dist/web/characters`).
  - 판정은 서버 시작 때 한 번. 그림을 바꾸면 파일만 바꾸면 되고(같은 경로), 폴더를 바꾸면 서버를 다시 켠다.
- `config.ts`: `charactersDir: string | null`, 기본 `null`.
- `doctor`: 「그림 묶음」 줄 — 진짜 묶음 경로 ✓ / 대체 그림 사용 중(정보) / 설정했는데 유효하지 않음 ⚠(이유).
- README: 「그림 묶음」 절(모양·`charactersDir`·대체 그림 다시 만들기) + 「라이선스」 절(코드와 대체 그림 = MIT, 갈무리 = OFL).
- `LICENSE`: MIT, 저작권자 자리는 `[이름 — 공개 전에 채움]`.

## 5. 대체 도트 사람

> 2026-11-06 바뀜(사용자): 처음 안(도형으로 찍는 스크립트)은 시험본이 "안 예쁘고 구도도 안 맞음"(정면·곧은 다리)으로 기각 → **제미나이로 글 설명만으로 생성 + 도트 변환**.

- 생성: 기본 캐릭터 한 명을 제미나이 앱에서 **참고 그림 없이** 글로만 요청 — 서기 앞·뒤, 걷기 8동작 앞·뒤, 앉아서 타자 앞·뒤, 앉아 쉬기 앞(7장). 뒤 요청에는 이 과정의 결과만 붙인다. 요청문은 비공개 쪽(위키 작업 폴더 키트)에 둔다.
- 변환(비공개 그림 레포 `stand-in/`의 Python 도구): 원래 도트 격자 복원 → 머리 폭 35도트 기준으로 같은 배율 → 진짜 그림에서 잰 자리(서기 SE 맨 아래 줄 90·머리 가운데 x 31.5, NW 88·31.0, 앉기 SE 88·31.5, NW 86·30.5)에 놓기 → 32색으로 줄이기 → 워터마크·부스러기 지우기.
- 방향: 제미나이 앞모습 = SE, 뒷모습 = NW(얼굴이 향한 쪽을 재서 확인). SW·NE는 좌우 뒤집기.
- 층: 머리(목 위 + 머리카락) = `hair/<h>/head`, 나머지 몸 = `outfit/<o>/torso`, 다른 층은 빈 그림.
- 여덟 모습 = 머리색 넷(머리 모양은 하나 — 사용자) × 웃옷·바지 색 여섯 벌. 모두 바지.
- 표정: 입 모양만(neutral 그대로 · focused 일자 · soft 작은 웃음 · happy 벌린 웃음), 뒷모습 얼굴 층은 빈 그림.
- 앉기: 팔을 몸 밖·살색으로 떼어 가까운 팔 장에(두 손), 먼 팔 장은 빈 그림. 손 단계 1·5 / 3·7에 아래·위 손 1도트 들기, 상체 단계는 같은 그림, 눈(SE) 반·감음은 눈 점만 살색으로 덮고 선. 쉬기 = 앉아 쉬기 앞(SE) / 팔 뺀 타자 뒷모습(NW).
- 라이선스: 코드와 같은 MIT, 만든 방법은 `web/public/characters/SOURCE.md`.

## 7. 순서

1. `agent-office-art` 비공개 레포 만들고 채워 올림.
2. `art-pack` 브랜치에서 4~6절 구현(로컬 커밋만).
3. Codex 리뷰(`codex exec`, 임시 사본) + 시험 보드 두 번(대체 그림 / 진짜 묶음).
4. 이력 정리: 옛 커밋(`95959c8`까지)에서 `web/public/characters/`·`docs/mockups/`를 빼고, `art-pack` 커밋을 그 위에 얹는다. 옛 레포(`old-private`)의 두 폴더 모든 파일 지문(blob)이 새 이력에 하나도 없는지 확인.
5. `agent-office` 삭제 후 다시 만들기(비공개) → 정리된 `main` 올림. **삭제는 그때 사용자 확인.**
6. 맥 전환: 작업 폴더를 새 이력으로, `charactersDir` 설정, 다시 설치, 설치본에서 지금 그림 확인.

## 8. 위험과 대응

- 이력 정리 중 대체 그림까지 지워짐 → 4단계는 옛 커밋만 거르고 새 커밋은 그 위에 얹는다(같은 경로라 통째 거르기 금지).
- 진짜 묶음 경로가 틀려 설치본이 대체 그림으로 뜸 → doctor 경고 + 6단계 화면 확인.
- 옛 worktree 14개·옛 브랜치는 옛 이력(그림 포함) → 새 `origin`에 올리지 않는다(추적 원격은 `old-private`).
- 앞으로 진짜 그림이 찍힌 캡처는 공개 레포에 넣지 않는다(그림 레포 `mockups/` 또는 위키 작업 폴더).
