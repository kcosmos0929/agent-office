## 3. 범위

1. **세션 목록 파일 연동** — Claude 앱이 쓰는 `~/.claude/sessions/<pid>.json`을 읽는다.
2. **상태 3개 추가** — ❓ 질문 대기 · ⏳ 토큰 기다림 · 🧹 대화 정리 중.

## 4. 신호

### 4-1. 세션 목록 파일 ("등록부")

Claude 데스크톱 앱이 세션마다 `~/.claude/sessions/<pid>.json` 파일을 하나씩 쓴다. 이미 확인한 사실:

| 확인한 것 | 결과 | 언제 |
|---|---|---|
| 질문을 띄우면 | `status`가 `busy → waiting`으로 즉시 바뀜 | 2026-10-22 스파이크 |
| 답하면 | `waiting → busy`, 약 0.1초 안 | 2026-10-22 스파이크 |
| 답을 마치면(차례 끝) | `idle` | 2026-10-23 (살아 있는 세션 2개) |
| `sessionId` = 훅의 `session_id` | 같음 | 2026-10-23 (이 세션) |
| `kind` · `entrypoint` | `interactive` · `claude-desktop` | 2026-10-23 |
| 권한 요청 창이 뜨면 / 승인하면 | `waiting` / 승인 4초 뒤 `busy` | 2026-10-23 실제 확인 |
| **거절하면** | `waiting → idle` (Stop 훅 없이 차례가 끝남) | 2026-10-23 실제 확인 |
| `/compact` 동안 | `busy` 17초 → `idle` | 2026-10-23 실제 확인 |
| `waiting`이 나타나는 때 | 승인·질문 창이 떠 있을 때만 (세션 2개, 7번) | 2026-10-23 실제 확인 |

**읽는 필드는 7개뿐**: `sessionId`, `pid`, `kind`, `cwd`, `name`, `status`, `statusUpdatedAt`. 나머지(통신 소켓 경로 등)는 읽지도 저장하지도 않는다. 파일에 쓰지 않는다.

**읽는 방법**: 폴더 변화를 감시하고(`fs.watch`), 놓칠 때를 대비해 **2초마다 전체를 다시 읽는다**. 쓰는 중이라 JSON이 깨진 파일은 건너뛰고 다음 차례에 다시 읽는다. `kind`가 `interactive`인 것만 쓴다.

**규칙**:

- **R1 승인·답변 순간** — 우리 상태가 ❗ 승인 필요 또는 ❓ 질문 대기인데, 등록부가 `busy`이고 그 `statusUpdatedAt`이 우리가 대기에 들어간 시각보다 뒤라면 = 사용자가 답했다.
  - 남은 대기(메인·하위 에이전트 전부)를 지운다.
  - ❗였으면 → 승인한 도구의 활동(📖/✏️/▶, 모르면 ▶ 실행 중).
  - ❓였으면 → 💭 생각 중.
  - ~~거절해도 등록부는 `busy`로 간다~~ → 실제 확인 결과 거절하면 `idle`로 간다 → R6.
- **R2 연달아 대기** — 등록부가 `waiting`인데 우리 상태가 일하는 묶음이고 2초 안에 훅이 안 오면 → ❓ 질문 대기. (하위 에이전트 두 개가 동시에 승인을 요청해 앱이 차례로 묻는 경우 등)
  - 2026-10-23 실제 확인에서 `waiting`이 승인·질문 창일 때만 나타나 **켬**(`REGISTRY_WAIT_RULE = true`).
- **R3 훅 없는 세션** — 등록부에만 있고 훅 신호가 한 번도 안 온 세션도 캐릭터·목록 줄로 보여 준다.
  - `busy` → 💭 생각 중, `waiting` → ❓ 질문 대기, `idle` → ✅ 끝남·내 차례(30분 지나면 기존 규칙대로 😴).
  - 그 세션에서 훅이 오는 순간부터는 훅 기준으로 돌아간다.
  - **'훅 없음' 판정**: 등록부가 `busy`/`waiting`인 채로 **2분 넘게** 지났는데(서버가 켜진 시각부터 잼) 서버가 켜진 뒤 그 세션의 훅이 **한 번도 없을 때**. 이 판정 하나를 목록 태그(5-3)와 연결 띠(7장)가 같이 쓴다.
    - 서버를 막 다시 켠 직후 조용한 세션에 태그가 붙는 걸 막으려고 '일하는 중'일 때만 본다.
    - 긴 도구 실행(분석 10분 등)은 시작 훅이 이미 왔으므로 걸리지 않는다.
- **R4 퇴근** — 전에 보였던 등록부 파일이 사라지거나 그 `pid`가 죽으면 → 👋 퇴근(SessionEnd 훅이 안 와도). 이후는 기존과 같다(10분 뒤 목록에서 빠짐). 등록부에 한 번도 안 나타난 세션에는 적용하지 않는다.
  - 파일을 쓰는 도중이라 잠깐 안 읽히는 경우가 있어서, **두 번 연속** 안 보일 때만 퇴근으로 본다.
  - 퇴근한 세션이 등록부에 다시 나타나면(이어서 열기 등) 다시 보여 준다.
- **R5 제목** — 등록부 `name`이 있으면 그걸 제목으로 쓴다(앱에서 이름을 바꾸면 바로 반영). 없을 때만 기존 방식(트랜스크립트의 사용자 지정 제목)을 쓴다.
- **R6 거절·중단 뒤 내 차례** (2026-10-23 실제 확인으로 추가) — 기다리거나 일하던 세션(응답 없음 포함)의 등록부가 마지막 훅보다 나중에 `idle`이 되면 → ✅ 끝남·내 차례.
  - 거절하면 Stop 훅 없이 차례가 끝나서, 전에는 다음 입력까지 ❗가 남았다(실측 10초).

### 4-2. 훅 — 새로 받는 3개 + 기존 훅의 새 해석

훅 이름·필드는 공식 문서(code.claude.com/docs/en/hooks, 2026-10-23 확인)를 따른다.

| 신호 | 필드 | 상태 |
|---|---|---|
| **PreCompact** (새) | `trigger`: `manual`/`auto` | 🧹 대화 정리 중 |
| PreCompact `auto`인데 일하는 중이 아니거나(쉼·기다림·퇴근)·메인 도구가 열려 있거나·차례가 끝나 도우미만 일함, 또는 처음 보는 세션 · 도우미(`agent_id`)의 PreCompact (2026-10-27 추가) | Claude Code 2.1.308의 **미리 정리**: 쉬는 동안·도구를 돌리는 동안 다음 정리본을 뒤에서 미리 만들며 이 신호만 보내고, PostCompact는 다음에 실제로 바꿔 낄 때(차례 안) 온다. 실측: 11:07에 차례가 끝난 세션에 12:02 PreCompact만 오고 기록 파일·등록부엔 변화 없음 → 15분 뒤 '응답 없음' | **그대로**(상태·자리·세션의 마지막 신호 시각을 안 바꿈 — 숨은 세션도 다시 안 나타남, R6 보정도 막지 않음). 🧹로 보여 주는 자동 PreCompact도 R6 기준 시각은 안 바꿔, 구별 못 한 미리 정리는 등록부 쉼이 바로잡음. 남긴 판정: 차례 끝 뒤 도우미가 남은 채 메인이 이어 가 진짜 정리하면 잠깐 🧹 대신 👥(PostCompact에 💭) |

| **StopFailure** (새) | `error`: `rate_limit` | ⏳ 토큰 기다림 |
| StopFailure, 그 밖의 `error` | `overloaded`, `server_error` 등 | ✅ 끝남·내 차례 + 상세에 "오류: overloaded" |
| PreToolUse `AskUserQuestion` | `tool_name` | ❓ 질문 대기 |

| Notification `elicitation_dialog` · `elicitation_url_dialog` · `agent_needs_input` | `notification_type` | ❓ 질문 대기 (지금은 ❗로 처리) |
| Notification `quota_auto_resume_fired` | | 💭 생각 중 (한도가 풀려 자동으로 이어 감) |
| Notification `quota_auto_resume_stale` · `quota_auto_resume_disabled` | | ✅ 끝남·내 차례 (자동으로 안 이어 감 → 내가 할 차례) |
| Notification `permission_prompt`, PermissionRequest | | ❗ 승인 필요 (그대로) |

- `quota_auto_resume_*`의 뜻은 문서에 적혀 있다(fired = 이어 감, stale = 맥이 30분 넘게 잠든 사이 풀려서 Enter를 기다림, disabled = 이어 가지 않고 대기 끝). **실제로 받아 본 적은 없다** → 13장.
- 한도에 걸리면 `idle_prompt` 알림이 오지 않는다(문서). 그래서 ⏳는 시간이 지나도 😴로 바뀌지 않는다.

- **설치**: 받는 훅이 11개 → 14개(PreCompact, PostCompact, StopFailure 추가). **다시 설치해야 한다**(사용자 허락 후).

## 5. 상태 모델 변경

### 5-1. 새 상태 3개

| 상태 | 묶음 | 3D 오피스 | 말풍선 색 | 소리 |
|---|---|---|---|---|
| ❓ 질문 대기 | 🟠 급함 | 일어나 손 흔듦(❗와 같음) | 주황 | 알림음(❗와 같음) |
| 🧹 대화 정리 중 | 🔵 일함 | 생각하는 자세 | 일함 색 | 없음 |
| ⏳ 토큰 기다림 | ⚪ 쉼 | 책상에 엎드림 | 회보라 | 없음 |

- ❗와 ❓가 둘 다 걸려 있으면 ❗를 보여 준다(승인이 더 급함). 대기마다 종류(승인/질문)를 함께 기억한다.
- ❗ ↔ ❓로만 바뀔 때는 알림음을 다시 울리지 않는다.
- 🧹가 15분 넘게 신호 없으면 💭와 똑같이 '… 응답 없음'으로 바꾼다.
- **백그라운드 도우미** (2026-10-23 다시 설치 뒤 실제 확인으로 추가): 도우미 도구(Agent)가 바로 끝나고 도우미는 뒤에서 일하는 경우가 있다.
  - 메인 차례가 끝나도(Stop) **도우미의 승인·질문 대기는 지우지 않는다**(❗ 유지). 전에는 2초 만에 ✅로 바뀌어 대기를 놓쳤다.
  - 메인 차례가 끝났는데 도우미가 아직 일하면 ✅ 대신 **👥 도우미 투입**. 마지막 도우미가 끝나면 💭(메인이 결과를 받아 이어 감), 안 이어 가면 등록부 idle·idle 알림으로 ✅.
  - 등록부는 도우미가 일하는 동안 `busy`라서, 등록부 `idle`이면 도우미 목록도 비운다.

### 5-2. 목록 정렬 (위에서 아래로)

❗ 승인 필요 · ❓ 질문 대기 → ✅ 끝남 → 일하는 중(🧹 포함) → … 응답 없음 → ⏳ 토큰 기다림 → 😴 쉬는 중 → 👋 퇴근. 같은 칸 안에서는 오래된 순(지금과 같음).

### 5-3. '훅 없음' 표시

R3 판정에 걸린 세션은 목록 줄과 카드에 작은 회색 태그 **훅 없음**을 붙인다. 오피스에는 붙이지 않는다.

## 6. 대화 게이지

**무엇**: 이 세션의 대화가 모델의 기억 창(컨텍스트 창)을 얼마나 채웠나.

**어떻게 읽나**:
1. 훅으로 받은 트랜스크립트 파일(`transcript_path`)의 **끝 256KB만** 읽는다. 거기서 못 찾으면 1MB까지 한 번 늘린다. 그래도 없으면 게이지를 비운다.
2. 뒤에서부터 `type: "assistant"`이고 `isSidechain`이 참이 아닌(하위 에이전트 제외) 첫 기록을 찾는다. `model`이 `<synthetic>`(오류 안내용 가짜 기록)이거나 사용량이 전부 0이면 건너뛴다.
3. 사용 토큰 = `input_tokens + cache_creation_input_tokens + cache_read_input_tokens + output_tokens`.
4. 그보다 뒤에 **대화 정리 경계 기록**이 있으면 "정리 직후 — 다음 답부터 다시 계산"으로 비운다. 경계 기록은 `"type":"system","subtype":"compact_boundary"` 줄이다(2026-10-23, 실제로 정리된 이 세션의 트랜스크립트에서 확인).
- 대화 **내용은 저장하거나 보내지 않는다**. 줄을 해석할 때 메모리에만 잠깐 있고, 꺼내는 건 숫자(토큰)와 모델 이름뿐이다.

**언제 읽나**: 그 세션의 훅이 올 때, 세션당 **5초에 한 번까지**. PostCompact 뒤에는 5초 제한 없이 한 번 더 읽는다. 훅 없는 세션(R3)은 경로를 몰라 게이지가 없다(—).

|---|---|
| `claude-opus-5`, `claude-sonnet-5`, `claude-haiku-5`, `claude-fable-5`, `claude-opus-4-6` 이후 4.x, `claude-sonnet-4-6` | 100만 |
| `claude-haiku-4-5`와 그 이전 모델 | 20만 |
| 표에 없는 모델 | % 없이 토큰 수만 보여 줌 |

> 표는 2026-10-23 기준이다. 구현할 때 모델 문서로 한 번 더 맞춘다.

**보이는 곳** (오피스 화면에는 없음):
- **목록 줄**: `대화 ▓▓▓░ 62%`(작은 막대 + 숫자).
- **카드**: `대화 62% · 약 62만 / 100만 토큰 · Opus 5.5`.
- 비율은 내림해서 정수로 표시한다.
- 색: 70% 미만 초록, 70~89% 호박색, 90% 이상 빨강. (69 초록 · 70 호박 · 89 호박 · 90 빨강)

## 7. 연결 상태 띠

**어디**: 목록형 머리줄 오른쪽 끝, 오피스 화면 오른쪽 위(글자는 HTML). 지금의 화면 전체를 덮는 '끊김' 덮개는 없애고 이 띠로 바꾼다. 끊겨도 마지막 화면은 그대로 보인다.

**네 가지** (위에 있을수록 우선):

| 띠 | 조건 |
|---|---|
| 🔴 끊김 — 다시 연결 중 | 화면과 서버 사이 연결(WebSocket)이 끊김 |
| 🟠 훅 신호가 안 와요 — 점검 필요 | R3 '훅 없음' 판정에 걸린 세션이 하나 이상 |
| ⚪ 연결됨 · 아직 신호 없음 | 서버가 켜진 뒤 훅이 한 번도 안 옴 |
| 🟢 연결됨 · 신호 12초 전 | 그 밖. 마지막 훅이 언제였는지(초/분/시간 전) |

**누르면** 작은 패널:
- 서버 켜진 시각
- 세션 수(훅 N · 훅 없음 M)
- 등록부 상태(읽힘 / 폴더 없음 / 못 읽음)
- 마지막 훅 시각
- "자세한 점검: 터미널에서 `npm run doctor`"
- 토큰 같은 비밀은 보이지 않는다.

## 8. `npm run doctor`

터미널에서 한 줄씩 ✓ / ⚠ / ✗ 와 한 줄 안내를 보여 준다. **✗가 하나라도 있으면 종료 코드 1.** 읽기만 하고 아무것도 고치지 않는다. 토큰을 출력하지 않는다.

| # | 점검 | ✗ / ⚠ 일 때 안내 |
|---|---|---|
| 1 | 서버 응답 (`/healthz`) | ✗ 서버가 꺼져 있음 → 아이콘 앱 또는 launchd 확인 |
| 2 | `endpoint.json` 있음 · 그 pid 살아 있음 · 권한 0600 | ✗ 없음/죽음, ⚠ 권한 |
| 3 | `settings.json`에 14개 이벤트마다 우리 훅이 있음 | ✗ 빠진 이벤트 이름 → 다시 설치 |
| 4 | 설치된 훅·상태줄 스크립트 = 레포 버전(내용 해시 비교) | ⚠ 다름 → 다시 설치 권장 |
| 5 | launchd 서비스가 돌고 있음 | ✗ |
| 6 | 마지막 훅 시각 | ⚠ 아직 없음(정보) |
| 7 | 등록부 폴더 읽힘 | ⚠ 없음(데스크톱 앱을 안 쓰면 정상) |
| 8 | 위키 허브 개수 | ⚠ 0개 → 위키 경로 확인 |
| 9 | 화면 파일(`dist/web/index.html`) 있음 | ✗ → `npm run build:web` |

6번과 7번은 서버에 물어본다. 새 주소 `GET /api/health`가 JSON을 준다: 켜진 시각, 마지막 훅 시각, 등록부 상태, 세션 수. 다른 GET과 같은 규칙(같은 기기 또는 토큰 쿠키)을 따른다. `/healthz`는 지금처럼 `ok`만 준다.

## 9. 데이터 형식 변경

- `Status` += `question`, `compacting`, `quota`.
- `OfficeEvent`:
  - 추가: `question`(대기 시작), `compact-start`/`compact-end`(`trigger`), `quota-wait`, `resume`.
  - `stop`에 선택 필드 `error`.
- `Agent` += `hookless: boolean`('훅 없음' 판정 결과), `context: { state: 'ok'; used; window: number | null; model } | { state: 'compacted' } | null`.
- `Snapshot` += `health: { startedAt; lastHookAt: number | null; registry: 'ok' | 'missing' | 'error'; sessions: number; hookless: number }`.
- 등록부는 사건이 아니라 '지금 목록'이라 이벤트로 바꾸지 않는다. `OfficeState.applyRegistry(목록, now)`로 넣는다.

## 10. 안전 · 개인정보

1단계 원칙(보기 전용, 대화 내용 저장 안 함)을 그대로 지킨다. 승인·거절 버튼은 C 묶음에서 따로 설계한다.

- **등록부**: 7개 필드만 읽기. 쓰기 없음.
- **트랜스크립트**: 끝부분 읽기, 숫자와 모델 이름만 꺼냄. 화면에는 숫자만.
- **훅**: 새 필드는 `trigger`·`error` 두 개. 요약·오류 원문은 안 보냄.
- **새 주소**: `/api/health` 하나(GET, 기존 접근 규칙). 새 POST 없음.
- **doctor**: 읽기 전용, 비밀 출력 없음.

## 11. 만드는 순서

0. **실제 확인 (사용자 도움 필요, 10분쯤)** — 설정은 바꾸지 않는다. 등록부 감시 스크립트와 지금 서버 상태만 지켜본다.
   1. 테스트 세션에서 권한이 필요한 명령을 시켜 **승인 1번, 거절 1번** → 등록부 `waiting`/`busy` 변화와 훅 순서 확인 (R1, R2).
   2. 테스트 세션에서 **`/compact` 1번** → 정리 중 등록부 값 확인.
   3. **질문(AskUserQuestion)** 1번 → PreToolUse 말고 PermissionRequest도 오는지 확인.
   - 결과는 진행기록에 적고, 어긋나면 설계를 고친 뒤 사용자에게 알린다.
1. 공통: 상태 3개 · 라벨 · 묶음 · 정렬 · 창 크기 표.
2. 훅 변환: 4-2 표 + 훅 스크립트 필드 + 설치 이벤트 14개.
3. 상태 정리기: 대기 종류 기억, 정리·한도 흐름, 15분 규칙.
4. 등록부 수집기 + R1~R5.
5. 대화 게이지 읽기.
6. 건강 정보 + `/api/health`.
7. 화면: 목록(게이지·태그·띠) · 카드 · 오피스(말풍선·자세·띠).
8. `npm run doctor`.
9. **다시 설치(사용자 허락 후)** → 실제 세션으로 한 번 더 확인.
10. PR → Codex 코드 리뷰.

## 12. 확인 방법

**자동 테스트** (실제 신호에서 내용을 지운 예시 사용):

| 대상 | 확인할 것 |
|---|---|
| 등록부 읽기 | 7개 필드만 꺼냄, 깨진 JSON 건너뜀, `interactive`만 |
| R1 | ❗/❓ 다음 `busy` → 활동·생각 중, 대기 전 시각의 `busy`는 무시, 메인·하위 대기 모두 지움 |
| R2 | `waiting` + 2초 무훅 → ❓, 훅이 먼저 오면 훅대로 |
| R3 | 등록부만 있는 세션 표시, 훅이 오면 전환, '훅 없음' 2분 판정 |
| R4 · R5 | 파일 사라짐/pid 죽음 → 퇴근, 처음부터 없던 세션은 영향 없음, `name` 우선 |
| 새 훅 | 4-2 표 전 줄 |
| 훅 스크립트 | `trigger`·`error`는 보내고 `compact_summary` 등은 안 보냄 |
| 게이지 계산 | 네 값 합, 하위 에이전트·`<synthetic>` 제외, 정리 경계 뒤 비움, 256KB → 1MB 확장, 모르는 모델 |
| 게이지 색 경계 | 69 / 70 / 89 / 90 |
| 정렬 · 소리 | 5-2 순서, ❗↔❓ 재알림 없음 |
| 연결 띠 | 네 가지 조건과 우선순위, '초/분/시간 전' 문구 |
| doctor | 9개 점검 각각 ✓/⚠/✗, ✗ 있으면 종료 코드 1 (가짜 HOME으로) |

**실제 확인** (사용자와 함께): 0단계 3가지 + 다시 설치 뒤 승인 순간·`/compact`·게이지 숫자가 앱 표시와 맞는지.

## 13. 아직 확인할 것

1. ~~권한 요청 때도 등록부가 `waiting`이 되는가, 거절 때는 어떻게 되는가~~ → 해결: 승인 창 `waiting`, 승인 `busy`, **거절 `idle`**(→ R6) (2026-10-23).
2. ~~대화 정리 경계 기록의 정확한 이름~~ → 해결: `compact_boundary` (2026-10-23).
3. ~~AskUserQuestion에 PermissionRequest도 오는가~~ → 해결: 온다(6초 뒤 `permission_prompt` 알림도 옴) → '질문'으로 분류, 알림은 무시 (2026-10-23).
4. **계획 승인(ExitPlanMode)** 때 PermissionRequest가 오는가 → 계획 모드를 쓸 때 확인. 안 오면 PreToolUse `ExitPlanMode`를 ❗로 보는 걸 제안한다.
5. `quota_auto_resume_*`와 StopFailure `rate_limit`을 실제로 받는 것 → 한도에 실제로 걸렸을 때. 그때까지는 문서대로 처리한다.
6. 한도 대기 중 등록부 값 → 5번과 함께.

## 14. 이번엔 안 하는 것

- 화면에서 승인·거절 → C 묶음.
- 산책·연출·이벤트·낮밤, 미감 다듬기 → B 묶음(미감은 디자인 세션과 함께).
- 오피스 화면의 게이지(설계 2 결정).
- 훅 없는 세션의 게이지(트랜스크립트 경로를 짐작하지 않음).
- 데스크톱 앱용 사용량 출처, Codex·ARIA 신호 → 별도 단계.

## 검토 때 봐 주세요 — 설계 1·2 뒤에 제가 정한 세부

결정에 가까운 것들이라 따로 모았다. 바꾸고 싶은 게 있으면 말해 주세요.

1. **승인 뒤 상태**: 승인한 도구의 활동(📖/✏️/▶)으로, 질문에 답한 뒤엔 💭 생각 중으로.
2. **한도 말고 다른 오류로 멈춤**(과부하·서버 오류 등): ✅ 끝남·내 차례 + 상세에 오류 종류.
3. **`quota_auto_resume_*`**: 이어 감 → 💭, 이어 가지 않음 → ✅ 내 차례.
4. **'훅 없음' 조건**: "일하는 중 2분 넘게 + 훅 0번". 긴 도구 실행이나 서버 재시작 직후에는 경보가 뜨지 않게.
5. **R2(연달아 대기)**: 0단계 확인 뒤에만 켬 → 2026-10-23 확인 후 켬.
6. **모르는 모델**: % 없이 토큰 수만.
7. **⏳는 알림음 없음**: 쉼 묶음이라. 바로 알아야 한다면 작은 알림음 추가 가능.
